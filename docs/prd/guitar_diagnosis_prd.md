# PRD: ギター上達診断アプリ（仮称）

**Status**: Draft ｜ **Author**: (自分) ｜ **Date**: 2026-08-14
**Context**: Alpha+プロジェクト（6ヶ月・ソロ推進）

## TL;DR
独学で伸び悩む社会人ギタリスト向けに、練習中に引っかかるフレーズを「スレッド」として記録し、過去の自分の演奏と比較することで、具体的にどこが停滞しているか・どこが伸びているかを可視化する、診断ファーストの練習伴走アプリ。

## Problem / Background
- 一人で練習しても自分の演奏の良し悪しが客観視できず、上達実感が持てない
- 何を練習すべきか自分で設計できず、なんとなく弾いて終わる
- 継続の仕組みがなく、練習が途切れがち

## Why Not Existing Apps
| | 既存アプリ（Yousician等） | 本アプリ |
|---|---|---|
| アプローチ | 用意されたカリキュラムを消化 | 自分の弱点をその場で診断 |
| 対象 | アプリのライブラリ内の曲 | 練習中の何にでも対応 |
| 進捗の見え方 | ゲーム内スコア・正解率 | 自分の過去の演奏との比較 |

## Goals（v1で目指すこと）
1. **（核）** ユーザーが、自分の練習のどこが伸びていてどこが停滞しているかを具体的に実感できる
2. コード進行の有無・曲か基礎練かソロかを問わず使える
3. スレッド単位の小さな達成の積み上げと、再開時に前回の続きがすぐ分かる設計で、継続のハードルを下げる

## Non-goals（v1ではやらない）
- 初心者向けゼロからのフルカリキュラム提供
- アプリ独自の曲ライブラリ・レッスンコンテンツの拡充
- 曲のコード名を自動判定する機能
- 曲通しの高精度診断（曲通しは簡易な記録機能に留める）
- バンド・セッションのマッチングなどソーシャル機能
- ギター以外の楽器対応
- 利用を促す通知・リマインド機能（v1では持たない）

## Target User / Persona
「島田さん（仮）、30代社会人、ギター歴3年、独学、自分の弾きたい曲は弾けるが上達が頭打ちになっている」

## Key Scenarios
1. 練習中に「ここが引っかかる」と感じたフレーズをスレッドとして作成（曲の一部・基礎練・ソロ、何でも可）
2. そのフレーズを録音 → スレッド内の過去テイクと比較し、安定度・変化を診断
3. 安定したらスレッドを「解決済み」に。まだ引っかかるならテイクを積み重ねる
4. アクティブなスレッドは少数に絞り、練習の焦点を保つ（具体的な上限は検証して決める）
5. 曲を通しで弾いた場合は「曲通しスレッド」として、完走回数・所要時間程度の簡易ログのみ記録する
6. しばらく開いていなかったスレッドを再開する際は、前回の診断結果からすぐ続けられる
7. （オプション）講師等に録音してもらったお手本演奏をスレッドに設定し、自己比較に加えて「お手本との一致度」でも診断できる

## Solution / Approach
- コアループ：フレーズスレッド内の複数テイクを自己比較し、ズレ・安定度の変化を検出する
- 外部の「正解」（コード進行・タブ譜・曲データベース）は不要。既存の音声解析技術を活用し、ゼロから高難度な認識技術を開発するリスクは避ける
- （オプション）自己比較だけでは「最初から間違えている／同じ間違いを繰り返している」場合に検出できない構造的な限界があるため、ユーザーが任意で講師等の録音を「お手本」としてスレッドに設定し、絶対比較もできるようにする。お手本も通常のテイクと同じ音声データとして扱うため、新たな認識技術の開発は不要（既存の自己比較エンジンをそのまま流用できる）

## Success Metrics
- Primary: 4週間後の週1回以上の練習ログ継続率（目標値はベースラインがないため未設定。ユーザーテスト後に設定する）
- Secondary: 解決済みスレッド数（ユーザーあたり）、診断機能の利用率、上達実感アンケートスコア

## Risks / Open Questions
- **自己比較は「一貫性・安定度」を測る仕組みであり、絶対的な正誤（音楽的に正しいか）を判定できない構造的な限界がある。最初から音を間違えている場合や、同じ間違いを毎回繰り返している場合でも、テイク間の類似度が高いため「安定している」と誤診断され得る** → UI上で「正しさ」ではなく「一貫性/変化」の指標であることを明示する。「解決済みにする」操作時に自己確認ステップを挟む、任意で講師等のお手本と絶対比較できるようにする（Solution/Approach参照）等で補うが、根本解消はできない前提として認識しておく
- 自己比較が、録音環境・機材が毎回揃わない自宅録音・下手な演奏でどこまで実用的か → M1で技術検証必須
- 和音（ストローク）と単音（フレーズ・ソロ）とで、自己比較の判定精度に差が出る可能性がある → M1の技術検証で確認
- スレッドの粒度をユーザーが迷わず区切れるUXになるか
- アクティブスレッド数を絞る設計が、逆にニーズを阻害しないか
- ユーザーテストの母数が自分一人に留まる可能性があり、結果の客観性に限界がある

## Rough Milestones（6ヶ月）
- M1: 技術検証（自己比較の精度）
- M2–3: MVP開発（フレーズスレッド作成・録音・比較診断の最小ループ）
- M4: 曲通しスレッド（簡易記録）の追加、UI/UX調整
- M5: 小規模ユーザーテスト・改善（自分が主なテストユーザーになる可能性が高く、可能な範囲で周囲にも依頼する）
  - （おまけ検証・Goalには含めない）余力があれば、同じ自己比較の仕組みがギター以外の単音楽器（オカリナ等）にも汎化するかを軽く試す。v1のGoal・Success Metricsには影響させず、あくまで将来の拡張可能性を確認する程度の位置づけとする
- M6: 成果まとめ・報告
