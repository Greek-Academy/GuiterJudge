# ideas-B: 情報設計とナビゲーションの視点から 10 案(B01〜B10)

提案者: シニア UX デザイナー(情報設計)/ 2026-09-23

## 前提: 現行の画面遷移(App.tsx と screens/*.tsx を読んだ結果)

```
一覧(ThreadList) ──「今日の一本 ▶ 録る」──> 詳細(ThreadDetail, autoRecord) ──■停止──> 診断(DiagnosisView)
   │  カードをタップ ─────────────────────> 詳細 (設定パネル → ●録音 → 推移 → お手本 → テイク履歴 → 解決)
   │  曲通しカード ──> 曲通し(SongThroughView)          診断 ──「もう 1 回」──> 詳細(autoRecord)
   └  最下部「検証」──> 検証(TranscriptionLab)          診断 ──「ホームへ」──> 一覧
```
- 画面は 5 つを useState で切り替え。戻るは常に「← 戻る」ボタン。URL 無し、端末の戻るボタン(Android)は効かない。
- 現行のタップ数(マイク許可済みの場合): **開く→録音開始 1 タップ**(hero の「録る」)、**診断→次の録音 1 タップ**(「もう 1 回」)。停止は毎回 1 タップ。
- 情報設計上の問題: (1) 詳細画面が「録音の前準備」「推移」「お手本」「履歴」「解決」を縦 1 本に詰めており、録音ボタンが設定パネルの下に沈む。(2) 診断画面が上から「対戦カード → 格子 → 比較モード → 6 指標 → ピアノロール」の長い一枚で、離れて見る用と手元で読む用が混在。(3) Android の戻るボタンで前の画面へ戻れない。(4) 設定(メトロノーム・最低音)が毎回目に入るが、変えるのはたまに。

以下の 10 案はすべてこの 1 / 1 を下回らないこと(同じか減らす)を最低条件にし、代わりに「何を主単位にするか」「何を先に見せるか」を変える。
タップ数の数え方: マイク許可済み、前回の設定が残っている、停止タップは含めない。「録音開始」= カウントインが鳴り始める時点。

共通の実装メモ(全案): どの案でも `history.pushState` ベースの最小ルーター(依存無し 50 行程度)を入れて Android の戻るボタンを効かせる。これは案の差ではないので各案のコストには含めない。

## B01 ワンボタン・スタジオ(起動即録音の単一画面)

**一言コンセプト**: 開いたら「今日の一本」の録音待ち画面がそのまま出ていて、アプリは実質 1 画面、ほかは全部そこから引き出すシート。

**ビジュアル言語**
- 色: 背景 #111315(ダーク既定)/ #F6F5F1(ライト)、録音ボタン #E5484D、待機リング #3A3F44、結果の「前回より揃った」側 #4CC38A、文字 #ECEDEE
- タイポ: 数字は等幅寄りのサンセリフ(`ui-monospace` 系、72〜120px)、見出し 20px、本文 15px
- 形: 画面の 60% を占める真円の録音ボタン。角丸は 24px のボトムシートだけ。影は使わず面の明暗で階層を作る
- ダーク既定(譜面台の横で眩しくない)、ライトはシステム設定に追従

**情報設計とナビゲーション**
- 画面は「スタジオ」1 枚。上端にフレーズ名(左右スワイプか ‹ › で切替)、中央に巨大な録音ボタン、下端に前回の結果の 1 行。
- 下から引き出すシートが 3 段: 半分(今回の診断の要約)→ 全面(詳しい診断: 格子・6 指標・ピアノロール)。上端のフレーズ名タップで「フレーズ一覧シート」。右上の ⋯ で設定・お手本・取り込み・バックアップ・検証。
- 録音停止 → 同じ画面のボタン位置に結果が「沈み込む」ように出て、ボタンは小さくなって下に残る。画面遷移なし。
- タブ無し、モード無し。曲通しは一覧シートの中の別行(開くと完走時間入力のシート)。

**タップ数**: 開く→録音開始 **1**(開いた時点で待機、ボタン 1 回)。設定で「開いたら自動で待機→カウントイン」を選ぶと **0**。診断→次の録音 **1**(同じ画面のボタン)。

**主要 3 画面のスケッチ**
```
[ホーム=スタジオ]              [録音中]                     [診断結果(半シート)]
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
│ ‹  Aメロの16分  ›    ⋯ │    │ Aメロの16分   ♩=92   │    │ Aメロの16分          │
│    ♩=92  16分        │    │                      │    │   ばらつき            │
│                      │    │        3             │    │    18 ms  (前回 24)  │
│      ╭────────╮      │    │    ● ● ● ○          │    │ 一致率 ○ 抜け ○ テンポ△│
│      │   ●    │      │    │   カウントイン        │    │ ──────────────────── │
│      │  録る   │      │    │                      │    │ 前回より揃っていた    │
│      ╰────────╯      │    │  ╭──────────────╮   │    │ 項目が 2 つ           │
│                      │    │  │    ■ 止める    │   │    │ ╭────────╮  詳しく ↑ │
│ 前回 24ms・きのう     │    │  ╰──────────────╯   │    │ │ ● もう1回│          │
│ ═══ 引き出す ═══      │    │                      │    │ ╰────────╯          │
└──────────────────────┘    └──────────────────────┘    └──────────────────────┘
```

**体験の核**: アイコンを押して、ギターを構え直す前にもう「録る」が目の前にある。録る→結果→録るが一切の画面遷移なしで回る。

**練習中の配慮**: 録音ボタンは画面幅の 70%、停止も同じ位置・同じ大きさ(指の位置を変えない)。結果の数字は 72px で 2 m から読める。音量キー(Android Chrome では取れないため)ではなく、画面のどこをタップしても停止できる「全面停止」モードを設定で提供。

**リスク・弱点**: 全体を俯瞰する場所が無く、フレーズが 10 本を超えると一覧シートが窮屈。推移グラフや解決などの「振り返り」がシートの奥に沈み、Goal #1(どこが伸びて停滞しているか)が弱くなる。誤タップで録音が始まる。

**実装コスト**: M(ボトムシート部品と画面の統合。既存の DiagnosisView はシート内にほぼそのまま入る)

## B02 セッション・ラン(練習セッションを主単位にする)

**一言コンセプト**: 「今日の練習」を 1 本の セッション として開始→フレーズを順に回す→終了で 1 枚のまとめ、というギター教室のレッスン形式を画面の骨格にする。

**ビジュアル言語**
- 色: 背景 #FAF8F3、セッション進行バー #2F6FDE、完了したフレーズ #7AA974、休憩・空白 #D9D4C7、文字 #1F1D1A。ダークは #16181B / #E6E3DC
- タイポ: 見出しは丸みのあるゴシック(`"M PLUS Rounded 1c"` 系か system-ui)24px、残り時間とカウントは 96px
- 形: 画面上端に常駐する細い進行バー(フレーズ数ぶんのセグメント)。カード角丸 16px、影は 1 段だけ
- ライト / ダーク両対応(ダークはセッション中のみ自動で切り替える選択肢)

**情報設計とナビゲーション**
- 画面の単位が 2 層: 「セッション外」(ホーム=前回のセッション記録と今日の献立)と「セッション内」(録音 → 診断 → 次へ、を献立の数だけ)。
- ホームの主ボタン「今日の練習を始める」で、アプリが今日の献立(冷えているもの・ゲージが満タン目前のもの・明日の予告があったもの から 2〜3 本)を提案。献立は並べ替え・差し替え可。
- セッション内は進行バー + 現在のフレーズの録音画面。診断は「要点カード」だけ出して、次のフレーズか同じフレーズのもう 1 回かを大きく 2 択。詳しい診断は終了後のまとめから辿る。
- 終了すると「セッションのまとめ」(今日録ったフレーズごとの前回比、明日の予告)が 1 枚。これが日誌として残る。
- タブ無し。フレーズ一覧・設定はホームの下段。

**タップ数**: 開く→録音開始 **2**(「始める」→ 献立確認画面の「1 本目を録る」)。献立確認を省略する設定で **1**。診断→次の録音 **1**(「もう 1 回」か「次のフレーズへ」、どちらも autoRecord)。

**主要 3 画面のスケッチ**
```
[ホーム]                       [録音中(セッション内)]       [診断結果(要点)]
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
│ ギター上達診断         │    │ ▰▰▱▱  2/4本目   9分 │    │ ▰▰▱▱  2/4本目        │
│ 前回のセッション 9/21 │    │ Cメジャー3度          │    │ Cメジャー3度          │
│  3本・12分            │    │                      │    │ ばらつき  21ms        │
│ ─ 今日の献立(案) ─   │    │          2           │    │  前回の自分 26ms      │
│ 1 Aメロ16分  冷え気味 │    │    ● ● ○ ○         │    │ ○揃い ○抜け無し △テンポ│
│ 2 Cメジャー3度 ■■■■□│    │                      │    │                      │
│ 3 F→Bb 持ち替え       │    │  ╭──────────────╮   │    │ ╭─────────╮╭───────╮ │
│                      │    │  │    ■ 止める    │   │    │ │↻ もう1回 ││次へ → │ │
│ ╭──────────────────╮ │    │  ╰──────────────╯   │    │ ╰─────────╯╰───────╯ │
│ │ ▶ 今日の練習を始める│ │    │ [終了]              │    │ 詳しくはまとめで      │
│ ╰──────────────────╯ │    │                      │    │                      │
└──────────────────────┘    └──────────────────────┘    └──────────────────────┘
```

**体験の核**: セッションを終えたときの「今日はこの 3 本を回した」まとめ 1 枚。レッスンを 1 回受けたような区切りが付く。

**練習中の配慮**: セッション内は画面を 3 要素(進行・フレーズ名・大ボタン)に限定。診断の 2 択ボタンは左右に分け、高さ 96px。セッション中は画面消灯を防ぐ(Wake Lock)。

**リスク・弱点**: 「セッションを始める」儀式が重い日もある(ちょっと 1 本だけ、が 2 タップになる)。献立の自動提案が外れると不満。セッションというデータ単位が新設になる(テイクの時刻から後付けで推定することで、既存データは移行不要にできる)。途中で止めた日の扱い(責めない表示)に配慮が要る。

**実装コスト**: M(セッションは takes の時刻から導出できる。新規は献立提案とまとめ画面)

## B03 練習ノート(タイムライン/日誌型フィード)

**一言コンセプト**: ホームは新しい順に流れる「練習ノート」のフィードで、テイクも発見も明日の予告も全部 1 本の時系列に並び、いちばん上に次の録音欄がある。

**ビジュアル言語**
- 色: 紙 #FBF9F4、罫線 #E7E2D6、インク #23211E、日付見出し #8A8173、書き込み(自分のメモ・予告)#3558B0。ダーク #141412 / #DAD5CA
- タイポ: 本文は明朝寄り(`"Noto Serif JP"` 系、16px)、数値は等幅 20px、日付見出しは 13px のスモールキャップ風
- 形: カードではなく罫線と余白で区切る。角丸はほぼ無し(4px)。影無し
- ライト既定、ダークは「夜のノート」として紙色を暗く反転

**情報設計とナビゲーション**
- 画面は「ノート」(フィード)と「ページ」(フレーズ別のフィード = 同じ部品をフィルタしたもの)の 2 種類だけ。フィードの各エントリ: テイク(要点 1 行 + 前回比)、発見、予告、解決、曲通しの完走時間、お手本の追加。
- 最上段は固定の「次に書き込む」欄: 今日の一本の名前と ● 録る。録音が終わると診断の要点がフィードの最上段に新エントリとして差し込まれる(画面遷移なし)。エントリをタップで詳細診断(全面)。
- フレーズ名をタップするとそのフレーズだけのページ(同じ時系列)に絞り込み、ページの上段にそのフレーズの推移グラフ。
- 空白日は「9/18〜9/20」と 1 行で畳み、何も言わない(責めない)。
- タブ無し。フィルタチップ(全部 / フレーズ別 / 曲通し)で切替。

**タップ数**: 開く→録音開始 **1**(最上段の ● 録る)。診断→次の録音 **1**(差し込まれたエントリの直下に「もう 1 回」)。詳細診断を開いていた場合は **1**(固定バー)。

**主要 3 画面のスケッチ**

```
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
│ 練習ノート  [全部▾]   │    │ 練習ノート            │    │ 練習ノート            │
│┌────────────────────┐│    │┌────────────────────┐│    │┌────────────────────┐│
││次: Aメロ16分  ● 録る ││    ││● 録音中  Aメロ16分  ││    ││次: Aメロ16分 ● もう1回││
│└────────────────────┘│    ││    4 拍目   0:07    ││    │└────────────────────┘│
│ 9/22 (月)            │    ││   ■ 止める          ││    │ 9/23 (火)  いま       │
│  Aメロ16分  24ms     │    │└────────────────────┘│    │  Aメロ16分  19ms      │

```

**体験の核**: 録り終えた瞬間、自分のノートの一番上に今日の 1 行が書き足される。過去の自分の記録が「読める文章」として下に続いている。

**練習中の配慮**: 録音中は最上段の欄だけが画面の上半分まで広がり(カウント 96px)、フィードは下に退く。遠目には「欄の色が赤 = 録音中」だけ分かればよい設計。

**リスク・弱点**: フレーズを横断して並ぶので、1 本のフレーズの推移を追うにはページに切り替える必要がある。フィードは長くなるとスクロール性能(仮想化)が要る。数字を 1 行に圧縮するため、指標の意味の説明を置く場所が少ない。

**実装コスト**: M(フィードの集約クエリと仮想リスト。診断詳細は既存流用)

## B04 4 つのタブ(今日 / フレーズ / 記録 / 道具)

**一言コンセプト**: 目的別に 4 つのボトムタブで棚を分け、「今日」タブだけが練習の主導線、残り 3 つは練習していない時間のための場所と割り切る。

**ビジュアル言語**
- 色: 背景 #F7F7F5、面 #FFFFFF、アクセント #2A78D6(現行を継承)、安定 #2E9E6A、注意 #C9822B、文字 #1B1C1E。ダーク #0F1113 / #1A1D21 / #E8EAED
- タイポ: system-ui(Roboto / Noto Sans JP)、タブラベル 12px、見出し 22px、主要数値 48px
- 形: Material 3 に近い角丸 12〜20px、タブバーは高さ 72px、FAB 無し
- ライト / ダーク両対応(prefers-color-scheme)

**情報設計とナビゲーション**
- ボトムタブ 4 つ:
  - **今日**: 今日の一本(大)、今日のまとめ、明日の予告。ここから録音・診断へ(タブバーは録音中と診断中に隠れる)。
  - **フレーズ**: アクティブ / 解決済み / 曲通し。フレーズ詳細は推移グラフ・お手本・テイク履歴・解決(録音ボタンは詳細の上端にも)。
  - **記録**: カレンダー + 期間ごとの推移(全フレーズ横断)。空白日は色を付けないだけ。
  - **道具**: メトロノーム単体、チューニング(最低音)、お手本取り込み、バックアップ、デモデータ、検証。
- 録音と診断は「タブの上に被る全面画面」(タブ外)。閉じると元のタブに戻る。
- 現行の詳細画面にあった設定パネルは「道具」とフレーズごとの設定シートに分割し、録音画面からは外す。

**タップ数**: 開く→録音開始 **1**(今日タブの「録る」。起動時は必ず今日タブ)。診断→次の録音 **1**(固定の「もう 1 回」)。フレーズタブ経由なら 2(フレーズ → 録る)。

**主要 3 画面のスケッチ**
```
[ホーム=今日タブ]              [録音中(全面)]              [診断結果(全面)]
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
│ 今日  9/23(火)        │    │ ×        Aメロ16分   │    │ ← Aメロ16分  9/23    │
│┌────────────────────┐│    │                      │    │ 前回の自分と          │
││今日の一本           ││    │         ♩=92         │    │ 揃い  19 vs 24 ms  ○ │
││Aメロ16分  ■■■□□   ││    │          3           │    │ 一致  94 vs 91 %  ○ │
││ ╭────────────────╮ ││    │                      │    │ テンポ +2 vs +1 % △  │
││ │     ● 録る      │ ││    │  ╭──────────────╮   │    │ ─ 拍に対する安定度 ─ │
││ ╰────────────────╯ ││    │  │    ■ 止める    │   │    │ [格子図]             │
│└────────────────────┘│    │  ╰──────────────╯   │    │ ─ ピアノロール ─      │
│ 明日の予告: ♩=96      │    │                      │    │┌────────────────────┐│
│──────────────────────│    │                      │    ││ ● もう1回   今日へ  ││
│ 今日  フレーズ 記録 道具│    │                      │    │└────────────────────┘│
└──────────────────────┘    └──────────────────────┘    └──────────────────────┘
```

**体験の核**: 迷わない。どこに何があるかが 4 語で説明でき、練習以外の作業(お手本の取り込み、バックアップ)が練習の邪魔をしない。

**練習中の配慮**: 録音・診断中はタブバーを隠し、誤タップの原因を消す。今日タブの「録る」は親指の届く下半分に置く。

**リスク・弱点**: もっとも汎用アプリ的で「このアプリらしさ」が出にくい。「記録」タブはカレンダーを置くとストリーク的に見えやすい(色の塗り方を「録った日に小さな点」だけに抑える必要)。タブが 4 つあると練習しない日に開いて眺めるだけになりがち(それ自体は悪くない)。

**実装コスト**: M(画面は増えるが各画面は既存部品の再配置。設定パネルの分割が一番手間)

## B05 フレーズ・デッキ(カードスタック、スワイプで次)

**一言コンセプト**: アクティブなフレーズが 1 枚ずつのカードとして重なっていて、今日はこれ・次はこれ、とめくりながら録っていく。

**ビジュアル言語**
- 色: 背景 #1C1B22(ダーク既定)/ #F4F2EE、カード面 #2A2833 / #FFFFFF、カードの冷え具合の縁取り 暖 #E0A45C → 冷 #6C8FB8、録音 #E5484D、文字 #F1EFEA
- タイポ: カードのフレーズ名 28px の太めのゴシック、数値 64px、補足 14px
- 形: 画面の 85% を占める縦長カード、角丸 28px、奥のカードが 8px ずつずれて見える重なり。影は下方向に 1 段
- ダーク既定 + ライト

**情報設計とナビゲーション**

## B07 コーチとの対話(チャット風、断定しない語り口)

**一言コンセプト**: アプリ全体が「練習仲間との会話」の 1 本のスレッドで、録音・結果・提案が吹き出しとして流れ、返事の選択肢(大きなボタン)で次に進む。

**ビジュアル言語**
- 色: 背景 #F3F1EC、アプリ側の吹き出し #FFFFFF、自分(テイク)の吹き出し #DCE8F7、返事ボタン #2A78D6、文字 #1E1E1E。ダーク #121212 / #1F1F1F / #22364F
- タイポ: 吹き出しは 17px の読みやすいゴシック、テイク吹き出し内の数値 32px、返事ボタン 18px
- 形: 吹き出し角丸 18px(送り側の角だけ 4px)、下端に返事ボタンの行(高さ 64px、最大 3 つ)
- ライト / ダーク

**情報設計とナビゲーション**
- 画面は「会話」1 枚 + 必要に応じて全面で開く「詳しい診断」「フレーズの設定」。会話はフレーズごとの話題で区切られる(上端の話題チップでフレーズ切替)。
- 開くと最新のメッセージ: 「きのうは Aメロ16分で 24ms でした。今日も録りますか?」+ 返事 [● 録る] [別のフレーズ] [今日は見るだけ]。
- 録音するとテイク吹き出し(波形 + 数値)が自分側に出て、アプリ側が「前回の自分と比べると、揃っていた項目が 2 つありました。3 拍目の裏が少し早めに出ていたかもしれません」と 1〜2 文。返事 [↻ もう 1 回] [詳しく見る] [次のフレーズ]。
- 文の生成はテンプレート(完全ローカル、LLM 不要)。「〜かもしれません」「〜でした」の事実+控えめ推量のみ、評価語(上手・下手)を辞書で禁止。
- タブ無し。フレーズ作成も会話で(「新しいフレーズを登録」→ 種類の 3 択 → 名前入力)。

**タップ数**: 開く→録音開始 **1**(返事 [● 録る])。診断→次の録音 **1**([↻ もう 1 回])。

**主要 3 画面のスケッチ**

```
││きのうは 24ms でした。│  │    ││♩=92 で録ります。    │  │    │        │▁▃▅ 19ms   │ │
││今日も録りますか?    │  │    ││カウントのあと 1拍目 │  │    │        │9/23 テイク │ │

│                      │    │     ● ● ● ○         │    ││揃っていた項目が 2 │  │
│╭─────╮╭──────╮╭─────╮│    │ ╭──────────────────╮ │    ││つ。3拍目裏が少し早 │  │

```

**体験の核**: 数字の意味を毎回ことばで添えてくれるので、指標を覚えていなくても「何が変わったか」が 1 文で分かる。返事ボタンを押すだけで練習が進む。

**練習中の配慮**: 返事ボタンは常に画面下端の同じ位置に 3 つまで、高さ 64px。録音中は会話を隠してカウントだけを大きく。読み上げ(Web Speech API の SpeechSynthesis、オフライン対応端末のみ)で 1 文を声で聞ける選択肢。

**リスク・弱点**: 「コーチ」の人格が PRD の断定しない方針とぶつかりやすい(推量表現でも助言に聞こえる)。文面のバリエーションが少ないとすぐ飽きる。数値を並べて比較したい人には遠回り。会話ログがデータとして増える(実際には保存せず、テイクから毎回再構成するのが良い)。

## B08 ビフォー / アフター(比較が主役)

**一言コンセプト**: すべての画面の中心に「前の自分 | 今の自分」の左右 2 列を置き、アプリの主語を「今日の点数」ではなく「2 つのテイクの差」にする。

**ビジュアル言語**
- 色: 背景 #F5F4F0、左列(過去)#B9B3A7 の落ち着いたグレージュ、右列(今)#1E6FD9、差が縮まった側の強調 #2E9E6A、差が開いた側 #C97A2B(赤は使わない)、文字 #1C1C1C。ダーク #111 / 左 #6E6A62 / 右 #5EA1FF
- タイポ: 左右の数値は同じサイズ(56px)で並べ、差分は中央に 20px。見出し 18px
- 形: 画面中央に縦の分割線(2px)。角丸 12px。影無し
- ライト / ダーク

**情報設計とナビゲーション**
- ホーム: フレーズごとに「前回 | 最新」の小さな対比行が並ぶ一覧。上段に今日の一本の対比(大)と ● 録る。
- 録音画面: 上半分に「比べる相手」(前回テイクのピアノロール縮小図 + 数値)、下半分に録音ボタン。録る前から「誰と比べるか」が見えている。

```
│  24 ms   │  ● 録る   │    │ ─────────────────── │    │  91 %     │  94 %   ○ │
│──────────────────────│    │                      │    │  +1 %     │  +2 %   △ │
│ Cメジャー3度          │    │         3            │    │ ▁▃▅▃▁     │ ▁▃▅▅▁     │
│  30 → 26 ms          │    │     ● ● ● ○         │    │ 3拍目裏: 右は少し早め  │
```

**練習中の配慮**: 左右 2 列の数値は 56px で 2 m から読める。録音画面で「比べる相手」を先に見せるので、録る前に意識するポイント(前回の弱点)が分かる。

**リスク・弱点**: 左右 2 列は縦持ちの 360px 幅だと窮屈(6 指標は縦並びの対比表に切り替える)。1 本目のテイク(比べる相手がいない)の画面が寂しい。曲通し(完走時間 1 つ)には過剰。

**実装コスト**: S〜M(現行の対戦カードと比較モードが既にある。レイアウトの組み替えが主)

## B09 練習台のダッシュボード(ウィジェット型)

**一言コンセプト**: ホームは自分で並べ替えられる小さなウィジェット(今日の一本、メトロノーム、今日のまとめ、ゲージ、予告、冷えたフレーズ)の盤面で、練習台の横に立てたスマホが「計器盤」になる。

**ビジュアル言語**
- 色: 盤面 #0E1116(ダーク既定)、ウィジェット面 #1A1F27、計器の針・目盛り #E8B04B(アンバー)、録音 #FF5A4E、安定 #56C58A、文字 #E6E9EE。ライト #F2F3F5 / #FFFFFF / #B7791F
- タイポ: 計器の数値は等幅の太字(`"JetBrains Mono"` 系 or `ui-monospace`)40〜80px、ラベル 12px の大文字小文字混在
- 形: 2 列グリッドのウィジェット(1×1 / 2×1 / 2×2)、角丸 14px、1px の縁取り。影無し
- ダーク既定、ライト対応

**情報設計とナビゲーション**
- ホーム = 盤面。既定の配置: 2×2「今日の一本(● 録る)」、2×1「メトロノーム(♩ と ± がその場で操作可)」、1×1「今日のまとめ」、1×1「明日の予告」、2×1「ゲージの並び(全フレーズ)」。長押しで編集モード(並べ替え・追加・削除)。
- 録音はウィジェット内で完結(2×2 がカウント表示に変わる)。停止すると「今日の一本」ウィジェットが結果表示に変わり、詳しい診断は全面へ。
- 横持ちにすると盤面が 4 列に広がり、譜面台に立てたときの計器盤として使える(このときだけ横持ち対応)。
- フレーズ一覧・フレーズ詳細は「すべてのフレーズ」ウィジェットから。道具類は右上 ⋯。
- タブ無し。

**タップ数**: 開く→録音開始 **1**(2×2 の ● 録る)。診断→次の録音 **1**(ウィジェット内の結果表示から直接「もう 1 回」)。全面の詳細診断からは **1**(固定バー)。

**練習中の配慮**: メトロノームの ± が盤面に常駐するので、テンポを上げ下げする往復が 1 タップ。横持ちで譜面台に立てたときに 4 列表示で情報量が増える。

**リスク・弱点**: 編集できる盤面は作る・テストする範囲が広い(ウィジェットの組み合わせ)。既定配置のまま誰も触らない可能性が高く、それなら編集機能は過剰投資。ウィジェットが増えると「計器だらけ」で断定しない静かさが損なわれる。

**実装コスト**: L(レイアウト編集・保存・横持ち対応。編集無しの固定盤面なら M)

## B10 譜面台モード(楽譜/タブ譜が主役、お手本がある時)

**一言コンセプト**: お手本(楽譜 MusicXML または講師録音)があるフレーズでは、画面の主役をタブ譜にして、録音も診断も「譜面の上に自分の音を重ねる」一枚で完結させる。お手本の無いフレーズは同じ枠をピアノロールで代用する。

**ビジュアル言語**
- 色: 譜面の紙 #FFFDF8、五線とタブ線 #4A4A48、お手本の音符 #2B2B2B、自分の音(揃い)#2A78D6、自分の音(早い/遅い)#D98A2B、弾き忘れ #A0A0A0 の点線、余分 #9B6BD1。ダーク: 紙 #16171A、線 #8C8C88、自分の音 #6FA8FF
- タイポ: タブ数字は等幅 18〜24px(拡大可)、見出し 18px、数値 40px
- 形: 画面の大半を譜面帯(横スクロール)に割く。UI 部品は譜面の上下の細い帯に収め、角丸 8px
- ライト既定(紙の譜面)、ダーク対応(夜間)

**情報設計とナビゲーション**
- ホーム: フレーズ一覧だが、各行にタブ譜の最初の 1 小節のサムネイル(お手本がない行は直近テイクのピアノロール縮小図)。上段に今日の一本。
- フレーズ画面 = 譜面台: 上 70% が譜面(お手本)、下 30% に ● 録る と ♩。録音中は譜面の上をカーソル(メトロノームの拍に合わせて進む)が走り、どこを弾いているかが分かる。
- 停止すると同じ譜面の上に自分の音が色付きで重なる(=診断)。ズレた音符の上に小さな印、タップするとその音の ms。譜面の下の帯に 3 項目の前回比と「もう 1 回」。詳しい 6 指標は帯を引き上げる。
- 比較の切替(直前 / 最も安定 / お手本)は重ねるレイヤーの切替として表現(お手本レイヤー、直前テイクのゴースト)。
- 和音の練習はコードタイムラインを譜面の代わりに、曲通しは譜面を使わない通常画面。
- タブ無し。

**タップ数**: 開く→録音開始 **1**(ホームの今日の一本 → 譜面台で autoRecord)。フレーズを選ぶ場合 **2**。診断→次の録音 **1**(同じ譜面台の下帯「もう 1 回」、画面遷移なし)。

**主要 3 画面のスケッチ**
```

│┌────────────────────┐│    │ e|--5-7-8-----------| │    │ e|--5-7-8-----------| │
││e|-5-7-8-|  Aメロ16分││    │ B|--------8-5-------| │    │ B|--------8-5̲-------| │
```

**体験の核**: 自分が弾いた音が、見慣れたタブ譜の上にそのまま色で乗る瞬間。「どこで」ズレたかが譜面の位置で分かる(数字を読まなくていい)。

**練習中の配慮**: 譜面台に立てて 1 m 先から読むことが前提なので、タブ数字は 24px まで拡大でき、拍カーソルは太い縦線。録音開始・停止ボタンは下端 30% の帯の中で最大化。画面の自動消灯を防ぐ。

**リスク・弱点**: お手本(楽譜)が無いフレーズが大半だと主役が不在になる(ピアノロール代用の見え方の質が鍵)。タブ譜の描画(弦・フレットの推定)は MusicXML に tab 情報が無い場合に推定が要り、誤ったフレットを見せると不信につながる。長いフレーズの横スクロールと自動追従の実装は重い。

**実装コスト**: L(タブ譜レンダラと重ね表示。既存の PianoRoll と scoreAlignment を土台にできるが描画は新規)
