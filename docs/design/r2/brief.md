# デザイン再コンペ 共通ブリーフ(2026-09-30)

## なぜ再コンペか
2026-09-24 のコンペ(docs/design/、優勝 F1「ひとつだけ」)を、ユーザーは採用しないことにした。理由はユーザーの言葉で **「毎日触りたくなるような UI ではない」**。前回の最終審査でも F1 は「毎日開きたくなる」が 3 点のまま優勝していた。今回はこの 1 点を最優先の課題とする。

参考としてユーザーが挙げたのは **Duolingo**。ただし「あまりそれに引っ張られないように」とも言っている。Duolingo の見た目(緑のフクロウ、ストリークの炎、XP、リーグ)を真似るのではなく、**なぜ毎日開いてしまうのか**(触って気持ちいい、画面に生き物っぽい反応がある、1 回が短くて区切りが明快、開いた瞬間にやることが決まっている、小さな達成が毎回ちゃんと祝われる、色と動きが明るい、など)を分解し、このアプリの思想の中で翻訳すること。

## お題
ギター上達診断 PWA(/Users/yk/dev/guitar/app/app)の **フロントエンド全体のデザイン(UI と UX)を全面的に作り直す** 前提で、全体コンセプト案を出す。現行の見た目・画面構成・遷移に縛られなくてよい。機能とデータは現行を引き継ぐ。

## プロダクトの芯
- 独学のギタリストが「引っかかるフレーズ」をスレッドとして登録し、録音したテイクを **過去の自分** と比べ、一貫性(ばらつき ms、音符一致率、弾き忘れ/余分、テンポ差)の変化を見る。
- スコアは **正しさではなく一貫性** の指標。「上達した」と断定しない。空白を責めない。
- 完全クライアントサイド、アカウント無し、オフライン PWA。
- 主な利用端末は **Android スマホ(Chrome)**、縦持ち。練習中は両手がギターで塞がる。1 回 5〜15 分。

## PRD の Non-goal と、今回の扱い
PRD はストリーク・XP・ランキング・通知を採用しないとしている。今回も既定ではこれを守る。ただし「毎日触りたくなる」を優先するため:
- ストリーク / XP / ランキング / プッシュ通知 **そのもの** は使わない。
- それらが担っている役割(戻ってくる理由、積み上がる手触り、祝われる瞬間)を、**責めない・比べない・断定しない** 形で実現する案を歓迎する。
- どうしても Non-goal に触れる要素を入れたい案は、その旨を「思想との衝突」欄に明記する(隠さない)。審査で減点はするが失格にはしない。

## 現行の機能(引き継ぐもの)
- スレッド一覧(アクティブ / 解決済み)、スレッド作成(単音フレーズ / 和音の練習 / 曲通し)
- スレッド詳細: 録音(マイク、メトロノーム + カウントイン、最小音価、最低音=変則調弦)、音声/動画ファイル取り込み、お手本(講師録音、既存テイク昇格、楽譜 MusicXML 取り込み)、テイク履歴、推移グラフ、解決(自己確認 3 択)
- 診断画面: 前回の自分との対戦カード(3 項目、発見)、拍に対する安定度、6 指標、比較モード切替(直前 / 最も安定 / お手本)、ピアノロール、和音はコードタイムライン、明日の予告、「もう 1 回録る」バー
- 毎日の型: ホームの「今日の一本」、今日のまとめ、明日の予告、安定ゲージ(5 目盛り)、スレッドの冷え
- 曲通し、検証画面(開発者向け)、デモデータ、バックアップ

## 前回のコンペから引き継ぐ知見(docs/design/round1-result.md, final-result.md)
- 効いた要素: 過去の自分を「居させる」表現(灰の前回値・残光・ゴースト)、練習中は画面の役割を変える(2 m 先から読める大きな数字・拍)、差が意味を持つかを正直に見せる「横ばいの帯(ノイズの帯)」。
- 減点された要素: スポーツ/射撃の「勝ち」、断定する語り口、リアルタイム推論や常時マイク前提の重さ、録音中にゴーストを見せて演奏を歪めること。
- 前回の最終候補 F1〜F4 と同じ案を出し直さない(発展させるのは可。その場合は何を変えたかを書く)。

## 審査の観点と重み(前回から変更)
1. **毎日触りたくなるか ×5**(開いた瞬間の気分、触り心地、戻ってくる理由、1 週間後・1 か月後も飽きないか)
2. 練習中の使いやすさ ×3(手が塞がる、1〜2 m 先から見る、大きな操作対象)
3. 診断結果が一目で分かるか ×2
4. このアプリらしさ ×2(汎用ゲーミフィケーションの貼り付けは減点)
5. 設計思想との整合 ×2(断定しない、責めない、比べない)
6. 実装の現実性 ×1(React + 素の CSS で段階的に移行できるか、アクセシビリティ、ダークモード、性能)

満点 75。

## 1 案の書式(全員共通)
- **ID と名前**
- **一言コンセプト**(1 文)
- **毎日触りたくなる仕掛け**(この案の核。Duolingo 的な何を、どう翻訳したか。1 日目 / 1 週間後 / 1 か月後に何が楽しいか)
- **ビジュアル言語**: 色(HEX 3〜5 個)、タイポ、形、モーション、ライト/ダーク
- **情報設計とナビゲーション**: 画面構成、主導線(開く→録る→見る)
- **主要 3 画面のスケッチ**: ホーム / 録音中 / 診断結果 を ASCII で各 10〜15 行
- **体験の核**: 一番気持ちいい瞬間
- **練習中の配慮**
- **思想との衝突**(あれば)、**リスク・弱点**、**実装コスト(S/M/L)**
