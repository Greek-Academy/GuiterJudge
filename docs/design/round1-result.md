# デザインコンペ 第 1 次審査の結果(2026-09-23)

審査委員長(プロダクトデザイン・ディレクター)。入力は brief.md と ideas-A〜E(50 案)。参考として ROADMAP.md(Q2「同じ演奏でのノイズの底」)、habit/competition-result.md 7 節の文言ルール、habit/shots の現行スクショ(ホーム・診断上部)を見た。

## 0. 審査の前提と総評

- 重み: 毎日開きたくなる ×3、練習中の使いやすさ ×3、診断の一目での分かりやすさ ×2、このアプリらしさ ×2、設計思想との整合 ×2、実装の現実性 ×1(満点 65)。
- 現行スクショで見えた課題は 3 つ。(1) 診断上部に注意書きが 3 行続き、主役の数字(13ms)が 2 番目のカードまで下がっている。(2) ホームは同じ形のカードが 5 枚並んでいて、「今日の一本」と他のスレッドの主従が色でしか分からない。(3) 画面全体が生成りと青の 1 トーンで、夜の練習部屋でも譜面台の距離でも同じ見え方をしている。
- 50 案を通して、効いているのは次の 3 点だった。
  - **過去の自分をどう「居させる」か**: 灰色の前回値、残光、ゴースト、鉛筆の書き込み、VU 針の移動元。
  - **練習中は画面の役割を変える**: ステージ、暗転、1 枚板、横持ち。
  - **差が意味を持つかどうかを正直に見せる**: D10 ノイズの帯。
- 減点が多かったのは次の 4 点。
  - スポーツや射撃の「勝ち」の連想(A10、D05)。
  - 断定しやすい語り口(B07、A08)。
  - リアルタイム推論や常時マイクが前提の重さ(C02、C09、C10、D08)。
  - 録音中にゴーストを見せると、演奏がそれに引っ張られて一貫性の計測が歪む点(C09、E06、A10)。
- ROADMAP Q2 との関係: どの案を選んでも、しきい値(4ms / 5pt / 1 個)はまだ較正されていない。そこで D10 のノイズの帯は **共通改善**(4 節)として全案に入れる。最終候補 4 の「ループ」は、同じ演奏を繰り返すことそのものが Q2 の計測になるので、この点も評価に含めた。

### F1「ひとつだけ」

- **構成要素**: A05 ひとつの数字(世界観) × B01 ワンボタン・スタジオ(導線) × C01 ワンボタン・ホール(練習中) × D01 ひとつの数字 + D10 ノイズの帯(診断) × E07 一問一答(語り口)

- **文言サンプル**
  - 付箋「次に書き込む」「✎ この 1 本を録る」「✎ もう 1 回録る」「✎ 指ならしに 1 本」
  - 文章テンプレート(verdict の結果と 1 対 1): 横ばい「前回とほぼ同じばらつきです(14 → 13ms)」/ 帯の外で小さい「前回より 7ms 小さいばらつきでした(24 → 17ms)」/ 帯の外で大きい「前回より 6ms ばらつきました(13 → 19ms)」/ 判定なし「今回は音が少なく、比べていません(8 音未満)」
  - 「〜しましょう」「上達」「良くなった」は辞書で禁止し、テストで禁止語を検査する。

- **想定リスク**
  - 伏せている間、「本当に録れているのか」と不安になる(鉛筆の線、経過秒、途切れたら赤)。
  - 可愛さが計測への信頼を損なう(数値は手書き風にしない)。
  - 定型文は繰り返すと飽きる(テンプレートは 1 状態 3 通りまでローテーション)。
  - 持ち曲には解決済みスレッドへの録音経路と、「解決した日」を比較相手に加える改修が要る(M)。
  - 明朝の長文はスマホ幅で縦に長くなる。

### F4「拍のループ」

- **構成要素**: B02 セッション・ラン(導線) × C06 ループ・ステーション(練習中)+ C05 拍の壁(カウントインと拍の表示) × D04 拍の時計(診断の固有図)+ D10 ノイズの帯(帯には同じセッション内のテイク間の揺れを使う) × E06 ゴーストと弾くの「位置の語彙」だけ(並んだ / 先に出た / 後から出た。録音中にゴーストは描かない)
- **なぜこの組み合わせか**: 引っかかるフレーズの練習とは、同じ数小節をメトロノームの上で何周も回すことだ。C06 はその形をそのまま画面にしている。1 回だけ触って始め、休みの小節で数字を見て、また弾く。カウントインは C05 の柱が 4→3→2→1 と消える表示にすると、2 m 先でも数字を読まずに入れる。1 日の単位は B02 のセッション(献立 2〜3 本)。診断は拍の上での位置を D04 の時計で見せる。語彙は E06 の「並んだ / 後から出た」に揃えて、勝ち負けの言葉を使わない。この案には Q2 に対する決定的な利点がある。同じセッションで連続して回した周は「同じ演奏の繰り返し」そのもので、ノイズの底を毎日自然に計測できる。その揺れがそのまま D10 の帯になる。
- **ビジュアル言語**
  - 色(ダーク既定): 背景 `#0D1017`、拍の柱 `#2D3142`、1 拍目の点灯 `#FFB000`、その他の拍の点灯 `#4F5D75`、今回の周・現在レーン `#3FA7D6`(縁は白 `#FFFFFF`)、前の周・過去 `#8A8F9C`、帯 `#1F2533`、文字 `#E9ECF2`
  - 早い / 遅いは色ではなく、▲(先に出た)/ ▼(後から出た)の形と文字で示す。赤は使わない。
  - ライト: 背景 `#F1EFF6`、柱 `#D9D6E3`、1 拍目 `#E09A00`、今回 `#1F6FB0`、文字 `#14121B`
  - 書体: コンデンスドの幾何学サンセリフ(`"Barlow Condensed", "Avenir Next Condensed", "Hiragino Sans", sans-serif` W600〜700)。拍番号 180px、レーンの数値 36px、ラベル 14px(等幅数字)
  - 形: 4 本の柱(柱間の溝 4px、角丸なし)、レーンは高さ 56px で角丸 8px、LED 風の 8px 四角で小節を示す。発光はしない(減光モード既定: 明るさの変化は 30% 以下、`prefers-reduced-motion` で点滅を止める)
  - 既定: ダーク

## 5. モック制作の仕様(次段の制作エージェント向け)

### 5.1 共通の作り
- **1 案 = 1 つの自己完結 HTML**。外部依存なし(CDN・Web フォント・画像ファイル禁止)。CSS と JS はインライン、図は インライン SVG か CSS で描く。文言は日本語。
- 出力先: `/private/tmp/claude-501/-Users-yk-dev-guitar-diagnosis/6c38de69-02bb-4678-ab7d-3ab1658633be/scratchpad/design/mocks/`
  - `f1-hitotsu.html` / `f2-booth.html` / `f3-notebook.html` / `f4-loop.html`
- 想定ビューポートは **390×844**(CSS px)。`<meta name="viewport" content="width=device-width, initial-scale=1">`。スマホ枠の装飾はしない(全画面)。`100dvh` を使う。
- 書体: Web フォントは使わず、3 節の各案の書体スタックをそのまま書く。撮影は macOS の Chrome で行うので、Hiragino(角ゴ・丸ゴ・明朝)で出る前提でよい。
- **画面遷移はクリックで行う**。同時に URL ハッシュでも直接開けるようにする(撮影を決まった状態で行うため。戻るボタンの実演も兼ねる)。
  - 共通ハッシュ: `#home` `#phrase` `#rec` `#diag` `#diag-bottom` `#extra`(案固有の画面)
  - `#rec` はカウントインを終えた「演奏中」の静止状態で開く。クリックでたどった場合は、カウントイン 4→1 のアニメーションを流してから演奏中に入る。
  - `#diag` は「体験の核」のアニメーションを終えた状態で開く。`?anim=1` を付けたときだけアニメーションを再生する(撮影は静止状態で行う)。
  - ハッシュを変えたら `history.pushState` を使い、ブラウザの戻るで前の画面に戻れるようにする。
- 右上か左下に小さな開発用トグル(ライト/ダーク切替)を置いてよい。撮影時は `?chrome=0` で隠せるようにする。
- アクセシビリティの最低限: ボタンは `<button>`、状態の色には必ず形か文字を併記する、主要な数字に `aria-label` を付ける(例: 「ばらつき 13 ミリ秒、前回 14、横ばい」)。
- 文言は competition-result.md 7 節のルールに従う。「上達」「良くなった」「勝ち」「達成」は使わない。数字には単位を付ける。横ばいは横ばいと書く。一貫性の注記を 1 画面に 1 回は出す。
