# ideas-E: 感情・語り口・長期の関係性からのコンセプト 10 案

担当視点: ブランド / 体験デザイン(初回体験、数週間〜数か月の手触り、解決したフレーズの記憶、調子の悪い日、アプリの人格と文言)
前提: brief.md の共通書式。ストリーク・XP・ランキング・通知は全案で使わない。competition-result.md 7 節の文言ルール(断定しない / 一貫性であって正しさではない / 空白を責めない / 解決は人が決める)を全案で守る。
例に挙がった方向(静かな伴走者、師匠の稽古帳、アーカイブ/博物館、季節・時間帯 UI、標本箱、手紙、スポーツ日誌、植物、段位、無言のツール)とは芯をずらしてある。

各案の共通追加項目:
- **初回起動の 60 秒**
- **調子の悪い日に何を見せるか**
- **3 か月後に開いたとき何が見えるか**

## E01 卓の向こうのエンジニア

**一言コンセプト**: アプリは「録音ブースのガラスの向こうにいるエンジニア」で、評価はせずに淡々とテイクを回し、スレートを読み上げ、プレイバックを用意してくれる。

**人格と語り口**: 口数は少ないが事務的ではない、スタジオの現場語。「テイク 12、回します」「いまのキープしときます」「プレイバック出せます」。褒めも叱りもしない。判断は常にプレイヤー(ユーザー)側にある、という関係。敬語は丁寧語止まり。

**ビジュアル言語**
- 色: 卓の黒 `#15171a`、ブースの木 `#b98a5a`、REC ランプ `#e0443e`、VU の琥珀 `#f2b33d`、文字 `#e9e6df`
- タイポ: 見出しは等幅寄りのサンセリフ(`"IBM Plex Sans JP", "Noto Sans JP"`、数字は `"IBM Plex Mono"`)。スレート番号は 40px、本文 15px
- 形: 角丸 4px の「チャンネルストリップ」型パネル、1px の細い罫線、影は使わず面の明暗で区切る
- ライト/ダーク: **ダーク既定**(ブースの照明を落とした感じ)。ライトは「昼のスタジオ」として生成り `#f4f0e8` + 墨文字に反転

**情報設計とナビゲーション**
- ホーム = 「今日のセッションシート」(トラックシートの行 = スレッド)。タブ無し
- 主導線: 開く → 行をタップ(= トラックにアーム)→ 大きな REC → 自動でプレイバック画面(診断)→「もう 1 テイク」
- 診断は「プレイバック」、テイク履歴は「テイクシート」、お手本は「リファレンス」と呼ぶ。解決は「OK テイクにする(本人判断)」

**主要 3 画面のスケッチ**

ホーム
```
┌──────────────────────────────────┐
│ SESSION  9/23(火)          ◐ 卓 │
│──────────────────────────────────│
│ 本日のトラック                    │
│ ┌──────────────────────────────┐ │
│ │ TR1 ソロ 12-16小節    ●ARM   │ │
│ │ 前回 T11 · 3日前 · ばらつき42ms│ │
│ │ ▮▮▮▯▯  同じ弾き方 3/5        │ │
│ └──────────────────────────────┘ │
│  TR2 Cコード→F 持ち替え  ○  5日前 │
│  TR3 曲通し「春」       ○  1週前 │
│                                  │
│ [ ● TR1 を回す ]                 │
└──────────────────────────────────┘
```
録音中
```
┌──────────────────────────────────┐
│ TR1 · TAKE 12            ● REC  │
│                                  │
│        ▌▌▌▌▌▌▌▌▌▌▌▌▌▎           │
│        -12 dB    ♩=92  3/4拍    │
│                                  │
│   「どうぞ」                     │
│                                  │
│                                  │
│ ┌──────────────────────────────┐ │
│ │        ■  止める             │ │
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```
診断結果(プレイバック)
```

│ PLAYBACK  TR1 T12 vs T11        │
│ 前回の自分と                      │
│  ばらつき  42 → 35ms   縮んだ     │
│  一致率    88 → 90%   横ばい     │
│  弾き忘れ   2 → 2     横ばい     │
│ ─ ピアノロール(T11 薄/T12 濃) ─  │
│  ▁▂▁▃ ▂ ▁▃▂ ▁▂  ← 9 音目で遅れ    │
│ 同じように弾けているか(一貫性)   │
│ の指標。正しさではありません      │

│ [ ● もう 1 テイク ]  [ 今日は終了 ]│
└──────────────────────────────────┘
```

**初回起動の 60 秒**: 暗いブースに REC ランプだけが灯る。「はじめまして。今日はどこを録りますか」とだけ出て、候補 3 つ(ソロの一部 / コードの持ち替え / 曲を通す)。選ぶとトラック名の入力(任意、空なら「TR1」)→ マイク許可 → 「テスト 1 本、回します」。最初のテイクは比較相手がいないので、プレイバック画面に「これが基準テイクになります。次のテイクからこれと並べます」。60 秒で「録って、並べる」という関係だけが伝わる。

**調子の悪い日**: エンジニアは絶対に顔をしかめない。3 項目が全部ばらついた日は「今日はここまでのテイク、全部シートに残してあります」と「テイクシート」への導線だけ出す。数字は隠さないが、見出しは「前回の自分と」のまま、色は赤ではなく琥珀の VU 色。3 テイク続けて数字が広がったら「一度ブースを出ますか」ボタン(今日は終了)を primary に上げる。

**3 か月後に開いたとき**: セッションシートの束。最上部に「このトラックの最初のテイク(T1, 6/20)と、いちばん最近の OK テイク」を並べて聴ける 2 つの ▶ だけの小さな帯。数字の総括は出さず、「T1 から 84 テイク回しました」と事実だけ。解決したトラックは「OK テイク」のスタンプ付きで下段に並ぶ。

**体験の核**: 録り終えた瞬間に何もしなくてもプレイバックが「出せます」と用意されていること。人に回してもらっている感覚。

**練習中の配慮**: REC/止めるは画面下 1/3 全幅。スレート番号と REC ランプは 2 m 先でも読める 40px+高輝度。カウントインは画面全体の明滅(ランプ)でも示す。

**リスク・弱点**: スタジオ語彙が分からない人がいる(「アーム」「スレート」)。→ 語彙は 5 語に絞り、初出だけ小注。ダーク既定は昼の窓際で見にくい。
**実装コスト**: M(語彙の置換と配色は S、プレイバックで T11/T12 の聴き比べは Blob 修正込みで M)

## E02 難所の踏査図

**一言コンセプト**: 1 本のフレーズを「山道」に見立て、テイクを重ねるたびに等高線の地図が描き込まれていき、どこが険しいか(ばらつく音)が地形として見えてくる。

**人格と語り口**: 山岳ガイドではなく「測量士」。道を歩くのはユーザー、アプリは等高線を引くだけ。「9 音目のあたりが急です」「この区間は前回より平らに測れました」。登頂・制覇という語は使わない(解決 = 「道がついた」)。

**ビジュアル言語**
- 色: 紙の地図 `#f3efe3`、等高線の茶 `#8a6a44`、水系の青 `#3c7a9a`、植生の緑 `#6f8f5a`、墨 `#2a2622`。ダークは夜間図 `#1b1f22` 地に淡い等高線 `#b9a988`
- タイポ: 地名風の明朝(`"Noto Serif JP"`)を見出しに 20〜28px、数字と注記はサンセリフ 13px
- 形: 角丸ほぼ無し(2px)、破線と細線、影なし。カードではなく「図郭」(紙の縁取り)
- ライト/ダーク: 両対応(昼の地図 / 夜間図)

**情報設計とナビゲーション**
- ホーム = 「いま歩いている道」一覧(アクティブは最大数本、それぞれ小さな地形の断面図がサムネイル)
- スレッド詳細 = 1 枚の地図。横軸 = フレーズの音の並び、縦の起伏 = その音のばらつき(過去 N テイクの格子ばらつき)。等高線の密度 = 険しさ
- 主導線: 開く → 道(スレッド)→ ● 歩く(録る)→ 断面図が今回の 1 本で描き直される(診断)
- 解決済み = 「道がついた」図として地図帳にとじる

**主要 3 画面のスケッチ**

ホーム
```
┌──────────────────────────────────┐
│ いま歩いている道        9/23     │
│──────────────────────────────────│
│ ソロ 12-16小節                   │
│   ‿‿⌒⌒⌒‿‿⌒‿    急: 9音目       │
│   3日前 · 11本                   │
│ ─────────────────────────────── │
│ C→F 持ち替え                     │
│   ‿‿‿⌒‿‿‿‿‿    急: 持ち替え直後 │
│   5日前 · 7本                    │
│ ─────────────────────────────── │
│ [ ● ソロ 12-16小節 を歩く ]       │
│            地図帳(道がついた 4) │
└──────────────────────────────────┘
```
録音中
```
┌──────────────────────────────────┐
│ ソロ 12-16小節 を歩いています     │
│                                  │
│  ● 00:07      ♩=92   2小節目    │
│                                  │
│   ・・・・●                       │
│   (いま置いた音が点で進む)       │
│                                  │
│                                  │
│ ┌──────────────────────────────┐ │
│ │        ■  止める             │ │
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```
診断結果
```
┌──────────────────────────────────┐
│ 今回の測量  (前回の自分と)       │
│   前回 ‿‿⌒⌒⌒‿‿⌒‿               │
│   今回 ‿‿‿⌒⌒‿‿‿‿               │
│         ↑ 7-9音目が前回より平ら  │
│  ばらつき 42→35ms / 一致 88→90%  │
│  弾き忘れ 2→2                    │
│ 平らさ = 同じように弾けている度合 │
│ い(一貫性)。正しさではありません │
│ いちばん急な所: 13音目(+18ms)    │
│ [ ● もう 1 回歩く ] [ 今日はここまで ]│
└──────────────────────────────────┘
```

**初回起動の 60 秒**: 白紙の図郭に「まだ測っていない道」と薄い破線が 1 本。「どこで引っかかりますか。そこが最初の道です」。種類 3 択 → 1 本録ると、破線の上に最初の起伏が描かれる(1 本だけなので「基準線」とラベル)。2 本目で初めて等高線が現れることを予告して終わる。

**調子の悪い日**: 起伏が荒れた日でも、地図は「過去全体の重ね合わせ」で描くので 1 本で地形が激変しない(直近 5 本の中央値)。今日の 1 本は細い赤茶の線として重なるだけ。文言は「今日の道は荒れて測れました。地形はこれまでの測量から描いています」。険しい地点が増えても「急: ◯音目」と地点を 1 つだけ指し、そこを遅いテンポで歩く提案(テンポ半分の ● ボタン)。

**3 か月後に開いたとき**: 地図帳に 6〜8 枚の図。各図の端に「最初の測量(6/20)」の断面が薄く残っていて、今の断面と重なって見える。平らになった区間は緑に塗られる。「上達」とは書かず、「6/20 の断面と今の断面」と並べるだけ。解決した道の図には「道がついた日 8/31」と本人が選んだ自己確認の答えが小さく記される。

**体験の核**: 2 本目を録った直後、白紙に初めて等高線が浮かぶ瞬間。「自分の引っかかりに形がある」と分かる。

**練習中の配慮**: 断面図は画面幅いっぱい・高さ 120px、2 m 先でも起伏の差が見える太さ(3px)。録音中は音が点で進むので、今どこを弾いているかが遠目にも分かる。

**リスク・弱点**: 音の並びが揃わない(弾き忘れ・余分が多い)テイクでは断面が描けない → 「測れた音だけで描いています(12/16 音)」と明記。和音スレッドはコード単位の断面にする必要がある。地形表現に凝ると描画コストが上がる。
**実装コスト**: M(断面は SVG の折れ線 + 帯。音ごとのばらつきは既存の格子ばらつき・アライメントの派生値)

## E03 手元の観測所

**一言コンセプト**: 調子は天気のように「観測するもの」で、責める対象ではない。アプリは手元の気象台として、今日の手の具合を観測記録に淡々と付けていく。

**人格と語り口**: 気象台の観測員。予報はしない(断定しない)、観測だけする。「本日の観測: ばらつき 35ms、前回観測より 7ms 小さい」「観測値の揺れが大きい日です」。晴れ・雨の比喩は **UI の形容として 1 語だけ** に留め、数字が主。

**ビジュアル言語**
- 色: 観測紙 `#f6f6f2`、記録ペンの紺 `#23395b`、晴れ間の水色 `#8cc4e0`、曇りの灰 `#9aa1a8`、日差しの黄 `#e9c46a`(警告色としての赤は使わない)
- タイポ: 観測表のようなサンセリフ(`"Noto Sans JP"`)、数字は表形式の等幅(tabular-nums)。観測値 48px、ラベル 12px
- 形: 方眼の背景(8px グリッドの淡い線)、角丸 6px、影なし
- ライト/ダーク: ダークは「夜間観測」`#12161c` 地に計器の淡緑 `#9fd8b8`

**情報設計とナビゲーション**
- ホーム = 「今日の空模様」: いちばん上に今日(またはまだ観測していない日)の手元の状態、その下にスレッド(観測地点)
- 各スレッド = 観測地点。詳細 = 観測簿(日ごとの行)
- 主導線: 開く → 「観測する」(= 今日の一本を録る)→ 観測結果(診断)→ もう 1 回
- 任意の「今日の体感」1 タップ(指が冷たい / 眠い / 普通 / 軽い)を観測メモとして残せる(C18 調子メモの再解釈)

**主要 3 画面のスケッチ**

ホーム
```
┌──────────────────────────────────┐
│ 手元の観測所          9/23 20:14 │
│──────────────────────────────────│
│ 今日はまだ観測していません        │
│ 前回観測 3日前:  ◐ 揺れやや大     │
│                                  │
│ 観測地点                          │
│ ・ソロ 12-16小節   ◑ 42ms  3日前 │
│ ・C→F 持ち替え     ○ 28ms  5日前 │
│ ・曲通し「春」     完走 3:12      │
│                                  │
│ [ ● ソロ 12-16小節 を観測する ]   │
│ 今日の体感: [冷] [眠] [普] [軽]   │
└──────────────────────────────────┘
```
録音中
```
┌──────────────────────────────────┐
│ 観測中  ソロ 12-16小節            │
│ ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │
│   ●  00:09                       │
│   ♩=92   ♪ ♪ ♪ ♪                │
│                                  │
│   入力レベル ▮▮▮▮▮▯▯            │
│                                  │
│ ┌──────────────────────────────┐ │
│ │        ■  観測を終える       │ │
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```
診断結果
```
┌──────────────────────────────────┐
│ 本日の観測  (前回の自分と)       │
│   ばらつき   35ms   前回 42ms    │
│   一致率     90%    前回 88%     │
│   弾き忘れ    2     前回 2       │
│ 空模様: ◑ 揺れやや大 → ◔ やや小   │
│ 観測簿  ▁▃▂▅▃▂▂  (日ごとの中央値) │
│ 体感メモ: 指が冷たい              │
│ 揺れの小ささ = 一貫性。正しさでは │
│ ありません                        │
│ [ ● もう 1 回観測 ] [ 今日はここまで ]│
└──────────────────────────────────┘
```

**初回起動の 60 秒**: 方眼紙に「観測を始めます」。「どこで引っかかりますか。そこを最初の観測地点にします」→ 1 本録る → 「最初の観測値です。空模様は 3 回観測すると出ます」。天気アイコンを初日から出さない(1 点では空模様は言えない、という態度自体がこのアプリの誠実さの自己紹介になる)。

**調子の悪い日**: この案の主戦場。数字が広がった日は「観測値の揺れが大きい日です」とだけ書き、その日の **体感メモ** を横に並べる(「眠い」を押していれば「眠い日の観測」)。観測簿では、体感メモ付きの日に小さな印が付き、後から「冷たい日は揺れが大きい傾向」のような **自分のコンディションと数字の関係** が見えてくる(断定ではなく「3 回中 3 回」の事実表記)。悪い日のデータは「失敗」ではなく「観測の厚み」。

**3 か月後に開いたとき**: 「観測 62 日分」の観測簿。月ごとの小さな気候図(各スレッドのばらつき中央値の月別)と、体感メモとの対応表。季節の変わり目(寒くなると指が…)も自分のデータで見える。解決したスレッドは「観測終了地点」として地図状に並ぶ。

**体験の核**: 悪い日の数字が「自分のせい」ではなく「今日の天気」として受け止められる。自分の手のクセ(寒い日・夜遅く)を自分のデータで知る。

**練習中の配慮**: 観測値 48px、空模様アイコンは 64px の単純図形(色覚に依存しない形の差: ○◔◑◕●)。体感メモは録音前後どちらでも 1 タップ、4 択の大ボタン。

**リスク・弱点**: 天気比喩が「運任せ」に聞こえ、練習の効果を感じにくくする可能性。体感メモの入力が続かないと主戦場が空洞化(任意にし、無い日は何も言わない)。空模様の閾値設計が要る。
**実装コスト**: M(体感メモは localStorage か Take への任意フィールド。後者なら Dexie 追加が要るので初期は localStorage で)

## E04 自分で書く教則本

**一言コンセプト**: 引っかかったフレーズは教則本の「課題」、テイクは余白への鉛筆の書き込み、解決は 1 章の完成。数か月で「自分専用の教則本」が 1 冊できあがる。

**人格と語り口**: アプリは「編集者」。書くのは著者(ユーザー)で、編集者は体裁を整え、目次を作り、「この章、そろそろ本文にしますか」と訊くだけ。文体は教則本の本文のように落ち着いた「です・ます」。

**ビジュアル言語**
- 色: 紙 `#fbf8f1`、本文墨 `#22201c`、鉛筆グレー `#7b7a74`、赤鉛筆(書き込みの強調、否定の意味では使わない) `#c0563b`、章扉の藍 `#2e4a6b`
- タイポ: 本文は明朝(`"Noto Serif JP"`)17px、行間 1.8。余白の書き込みは手書き風ではなく細いサンセリフ 12px のグレー(可読性優先)。章番号は大きな欧文数字 56px
- 形: 本のページ(左右の余白を広く、中央 1 段組)、角丸なし、罫線は細い単線、影は章扉だけに極薄
- ライト/ダーク: ダークは「夜の書斎」`#1c1a17` 地に生成り文字 `#e8e1d3`

**情報設計とナビゲーション**

## E06 ゴーストと弾く

**一言コンセプト**: 過去の自分は数字ではなく「ゴースト(半透明の自分の演奏)」として一緒に鳴り、一緒に流れる。比べる相手が画面の中に居る。

**人格と語り口**: アプリの人格 = 過去の自分。文言は過去の自分の視点を借りる: 「3 日前のあなたはここで 18ms 遅れていました」「今日は 9 音目で並びました」。勝ち負けは言わず「並んだ / 先に出た / 後から出た」の位置の語彙で話す。

**ビジュアル言語**
- 色: 夜の背景 `#101318`、今日の自分 `#f5f2ea`(実線)、ゴースト `#7fa7c9`(半透明 40%)、並んだ瞬間の光 `#ffd166`、補助 `#4b5563`
- タイポ: 幾何学サンセリフ(`"Inter"` + `"Noto Sans JP"`)、大きな数字は 44px、細身
- 形: 線と点だけ。カードなし、区切りは余白。角丸は丸ボタン(完全な円)のみ
- ライト/ダーク: **ダーク既定**(ゴーストの半透明が映える)。ライトは生成り地に墨の実線と淡い藍のゴースト

**情報設計とナビゲーション**
- ホーム = スレッドごとに「ゴーストの軌跡」(直近テイクのピアノロールを極小で重ねた帯)
- 録音中: 「ゴーストを鳴らす」オプション。前回テイク(またはいちばん安定したテイク / お手本)の音符列が画面を流れ、今日の音が同じレーンに点で置かれていく(音は鳴らさない既定、イヤホン時のみゴースト音を小さく鳴らせる)
- 診断: ピアノロールが主役。ゴースト(前回)と今日を重ね、ズレた音にだけ細い線
- 比較モード切替(直前 / 最も安定 / お手本)=「どのゴーストと弾くか」

## E07 一問一答

**一言コンセプト**: 1 テイクごとに、アプリがひとつだけ問いを出す(「どこで指が迷いましたか」)。数字と自分の感覚を照らし合わせることで、耳と手の自己認識が育つ。

**人格と語り口**: 答えを持たない聞き手。問いは短く、選択肢は 3〜4 個の大ボタン、答えなくてもいい。問いと数字を並べ、「あなたは 9 音目と答え、測定でも 9 音目が最も遅れていました」のように **一致したかどうか** だけ事実として返す。正誤は言わない。

**ビジュアル言語**
- 色: 白 `#fcfcfb`、墨 `#1d1d1f`、問いの色(やわらかな緑青) `#4a8c7e`、答えのハイライト `#d7ebe6`、補助グレー `#8e8e93`
- タイポ: 問いは大きく(28px、太め)、ゴシック系(`"Noto Sans JP"` 700)。数字 20px、注記 12px
- 形: 吹き出しではなく、左寄せの大きな問い + 下に並ぶ角丸 16px のピル型ボタン。影なし
- ライト/ダーク: 両対応。ダークは `#141615` 地に緑青を明るめ `#7cc2b0`

**情報設計とナビゲーション**
- ホーム = 今日の一本 + 「最近の問いと答え」(自分の答えの傾向)
- 主導線: 開く → ● 録る → **問い 1 つ(3 秒で答えられる)** → 診断(自分の答えと測定を並べる)→ もう 1 回

- 答えは任意、無答でも診断は出る

**実装コスト**: M(問いの UI は S。回答の保存は Take への任意フィールドで Dexie version +1、または localStorage でテイク ID キー)

**一言コンセプト**: テイクはフィルムの 1 コマで、1 日の練習は 1 本のロール。ベタ焼き(コンタクトシート)を眺め、自分でダーマトグラフの丸を付けた 1 コマが「このフレーズの今」になる。選ぶのは測定ではなく本人。

- ライト/ダーク: **ダーク既定**(暗室)。ライトは「プリントを明るい台で見る」: 印画紙白地に黒フチのコマ

- 1 日の練習 = 1 ロール。診断直後は「最新コマ」を大きく、下にその日のロール(ベタ焼き)

**初回起動の 60 秒**: 暗い画面に空のフィルム棚。「最初のロールを入れましょう。何を撮りますか(引っかかるフレーズ)」→ 種類 3 択 → 録音中は画面がセーフライトの赤に落ちる(録音中であることが一目で分かる演出を初回で体験)→ 「上がりました」で最初のコマ。「1 日の終わりに、その日のコマから 1 つ丸を付けられます」と一度だけ。

**調子の悪い日**: ベタ焼きには悪いコマも全部並ぶが、主線に乗るのは **本人が丸を付けたコマだけ**。荒れた日でも「今日の中でいちばんまし」な 1 コマに丸を付けて終われる(測定上の候補も出す)。丸を付けない日があってもよく、その日はロールだけ残る。「ネガは捨てません。プリントにするかはあなたが決めます」。荒れたコマが続いても推移グラフの主線は揺さぶられにくい(本人の選択が平滑化になる)。

**3 か月後に開いたとき**: スレッドごとに「丸の付いたコマ」を日付順に並べたプリント帯(1 日 1 コマ)。最初の丸と最近の丸を並べて聴ける。解決したスレッドは「プリント箱」に 1 枚のプリント(解決の日の丸)としてしまわれ、箱を開くと 10 枚前後のプリントが並ぶ。全テイクのネガも残っている。

**体験の核**: 1 日の終わりに自分で丸を付ける数秒間。測定を材料に、自分の耳と目で「今日の 1 本」を選ぶ主体性。

**練習中の配慮**: 録音中のセーフライト演出は「録っている/いない」を 2 m 先から色面で判別できる(色だけに頼らないよう REC 表示と経過秒も 48px)。丸付けは練習後なので手が空いている。

**リスク・弱点**: 丸付けの保存が必要(Take への任意フィールド)。「本人の選んだコマ」を主線にすると、測定の客観性と混ざる → 推移グラフでは主線(丸)と全テイク(淡い点)を必ず併記し、ゲージは従来どおり全テイクで計算。暗室の赤は目が疲れる人がいる(演出オフ設定)。
**実装コスト**: M(ロール = 日付でのグルーピングは派生値、丸付けは Dexie 追加 or localStorage)

## 横断メモ(10 案に共通する判断)

- **関係性の型**: 観察者型(E01 エンジニア / E03 観測所 / E10 暗室の先輩)、素材型(E02 地図 / E05 弾き込み / E09 作業台)、自己対話型(E06 ゴースト / E07 一問一答)、成果物型(E04 教則本 / E08 持ち曲帳)。組み合わせるなら「素材型のビジュアル + 自己対話型の文言」が相性が良い(例: E05 の艶 + E07 の問い)。
- **調子の悪い日の型**: (1) 1 本で景色を変えない(E02 中央値、E05 本数のみ、E10 本人の丸)、(2) できることで終える(E08 持ち曲、E09 研ぎ)、(3) 悪い日を情報にする(E03 体感メモ、E07 いたわる問い)。
- **解決したフレーズの記憶**: 最初のテイクと解決時テイクを「聴ける」ことが全案の共通要件。C19(聴き比べ、Recorder の Blob type 修正)が前提になる案が多い(E01 / E04 / E06 / E08 / E10)。
- **新規データ**: 追加の状態が要る案(E04 分かったことの 1 行、E07 回答、E09 研ぎタグ、E10 丸)は、初期は localStorage でテイク ID キーにしてバックアップ対象外、定着したら Dexie version +1 でまとめて移す、が段階移行の筋。
- **文言ルールの適用**: 全案で診断の見出しは「前回の自分と(または比較相手の名前)」、一貫性の注記 1 行、横ばいの閾値(4ms / 5pt / 1 個)、テンポを落とした回は勝ち扱いにしない、を維持する。比喩の語彙(削り・観測・艶・丸)は「上達」の断定の代わりに使わない(数字と方向を必ず併記)。
