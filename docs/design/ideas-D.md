# ideas-D: 診断結果とデータの見せ方から組み立てる全体コンセプト(D01〜D10)

視点: **診断の見せ方**(ばらつき ms・音符一致率・弾き忘れ/余分・テンポ差、前回の自分との比較、推移、ズレの位置)を核にして、その表現をホーム・一覧・録音中まで同じ文法で通す。

## 全案に共通する前提(各案の「数字の嘘をつかない」はこれを具体化したもの)

- **横ばいの幅は verdict.ts の既存値をそのまま使う**: ばらつき |Δ| < 4ms、一致率 |Δ| < 5pt、弾き忘れ/余分 |Δ| ≤ 1。この幅の中は「変化」として描かない(色も向きも付けない)。
- **判定しない条件も見た目に出す**: 対応音 / 格子音数が 8 未満、テンポを落とした回(メトロノーム bpm 低下、相対 tempoDiffPct < −8%)は「判定なし」の専用表現を持ち、勝ち負けの位置に置かない。
- **軸は 0 起点**(ばらつき推移は下限 0、上限は切りのいい値で最小 40ms)。二重軸は使わない。単位の違う指標は別の図か小さな複数図にする。
- **断定しない文言**: 「上達」「良くなった」は使わず、「前回より小さい / 横ばい / 前回よりばらついた」と方向だけ。各画面に「一貫性の指標で、音楽的な正しさではありません」を 1 回は出す。
- **色の役割**(dataviz スキルの方法論): 「前回の自分と今回」は *強調(emphasis)* 形式 = 今回だけアクセント色、前回・過去は灰。赤・警告色は「悪化」に使わない(責めない)。状態色(good/warning…)は系列色に流用しない。弾き忘れ・余分・音高違いは色だけでなく **塗り/中空/ハッチ** の形でも区別する(現行 PianoRoll の方針を継承)。
- **検証済みの色**(`validate_palette.js` を実行済み):
  - 今回 × お手本の 2 系列: light `#2a78d6` / `#eb6834`、dark `#3987e5` / `#d95926` → 全チェック PASS(CVD ΔE 24.7 / 26.8)
  - 3 系列(今回・お手本・3 つ目): light `#2a78d6,#eb6834,#1baf7a` は aqua が面に対して 2.74:1 で WARN → 直接ラベル必須。dark `#3987e5,#d95926,#199e70` は PASS
  - 暗色面で青 × 琥珀: `#3987e5` / `#c98500` → PASS(light の `#eda100` は 2.11:1 で WARN のため light ではラベル必須)
  - 連続量(ヒートマップ等)の単色ランプ: light `#86b6ef → #5598e7 → #256abf → #184f95 → #0d366b`、dark は同じ段を逆順(`#184f95` 始まり) → ordinal PASS。light で `#cde2fb` から始めると面とのコントラスト 1.29:1 で FAIL になるので使わない
- **全図に表(テーブル)ビューの双子**を付け、ツールチップだけで値を読ませない。ダークモードは自動反転ではなく上の段を選び直す。

## D01 ひとつの数字

**一言コンセプト**: どの画面も「今回のばらつき ms」という 1 つの大きな数字と、前回との差の 1 行だけで始まり、それ以外はすべてその数字の「内訳」として下に畳まれている。

**ビジュアル言語**
- 色: 面 `#f9f9f7`(dark `#0d0d0d`)、文字 `#0b0b0b`(dark `#ffffff`)、前回・補助 `#898781`、今回のアクセント `#2a78d6`(dark `#3987e5`)、横ばい帯 `#e1e0d9`(dark `#2c2c2a`)
- タイポ: 本文と同じサンセリフ(Noto Sans JP / system-ui)。hero 数字は 96〜120px、比例数字(tabular-nums は付けない)、単位 ms は 24px で数字の右下。前回との差は 20px
- 形: カードをやめ、罫線 1px とたっぷりした余白だけ。角丸は操作対象のみ 16px。影なし
- ライト/ダーク: 両対応。練習中はダーク推奨(譜面台で眩しくない)

**情報設計とナビゲーション**
- 3 階層だけ: ホーム(スレッドの数字の列)→ スレッド(数字 + 推移)→ 診断(数字 + 内訳)。タブ無し。戻るは左上と端スワイプ
- 主導線: ホームの最上段の数字をタップ = そのスレッドで録音開始 → 停止すると同じ場所に新しい数字が「差し替わる」→ 下に引くと内訳
- 内訳の順番は固定: 前回との 3 項目 → ズレの位置(ピアノロール)→ 残りの指標(テンポ差・対応音数・統合音)→ 比較モード切替

**主要 3 画面のスケッチ**
```

┌──────────────────────────────────┐
│ 今日の一本  Aメロのスライド        │
│                                    │
│          22 ms                     │
│   前回 26ms から −4ms(小さい)      │
│                                    │
│  [ ●  録る ]                        │
│──────────────────────────────────│
│ サビ前のフィル        31ms  横ばい │
│ Cコード→G            18ms  判定なし│
│ イントロのリフ        40ms  ばらついた│
└──────────────────────────────────┘
```
```
録音中
┌──────────────────────────────────┐
│ Aメロのスライド   ♩=80  16分       │
│                                    │
│            ● 0:07                  │
│                                    │
│          前回 26 ms                │
│   (この数字を今回の値で上書きします)│
│                                    │
│   カウント 1 2 3 4 のあと開始      │
│                                    │
│  [ ■ 止める(画面のどこでも) ]      │
└──────────────────────────────────┘
```
```

┌──────────────────────────────────┐
│ ← Aメロのスライド                  │
│          22 ms                     │
│   前回 26ms → 今回 22ms  −4ms       │

│ 比べる相手: [直前][最も安定][お手本]│
│  一貫性の指標。正しさではありません│
│ [ ● もう 1 回 ]        [ 一覧 ]     │
└──────────────────────────────────┘
```

**体験の核**: 停止ボタンを押して 1 秒後、2 m 先の画面で大きな数字がぱたんと差し替わり、その下に「前回 26 → 22」と出る瞬間。読むのは 1 つの数字だけ。

**数字の嘘をつかない**: 差が 4ms 未満なら差の行は「横ばい(−3ms)」と灰で書き、矢印も色も付けない。対応音 8 未満なら大きな数字の代わりに「—」と理由 1 行を出し、数字を大きく見せない。hero 数字を「良い/悪い」で色分けしない。

**練習中の配慮**: 数字 96px 以上で 2 m 先から読める。録音中は画面全体が停止ボタン。診断直後は音量を上げれば読み上げ(「22 ミリ秒、前回より 4 小さい」)も選べる。

**リスク・弱点**: 1 つの数字に寄せるとばらつき以外(弾き忘れ、和音の一致率)が軽く見える。和音スレッドでは hero を「切り替えのばらつき ms」に差し替える規則が要る。数字を大きくするほど 4ms の差が大事件に見えやすい → 横ばい表記の徹底が前提。
**実装コスト**: S(既存の stat-hero と VersusCard の再配置 + ダーク変数)

## D02 重ね録りの二段譜

**一言コンセプト**: 前回と今回の演奏を上下 2 本の「オンセットの線」として並べ、同じ音どうしを細い線で結ぶ(スロープ)ことで、「どの音が前回よりどっちにずれたか」を 1 枚で見せ、ホームのカードもこの 2 本線の縮小版にする。

**ビジュアル言語**
- 色: 面 `#fcfcfb`(dark `#1a1a19`)、前回の線 `#898781`、今回の線 `#2a78d6`(dark `#3987e5`)、お手本を 3 本目に出すとき `#eb6834`(dark `#d95926`)、結び線 `#c3c2b7`(dark `#383835`)
- タイポ: サンセリフ、指標は 28px、図中ラベル 12px の muted
- 形: 目盛り 1px のヘアライン、マーカー 8px の縦棒(オンセット)、角丸 4px。カードは 12px 角丸 + 影なしの 1px 枠
- ライト/ダーク: 両対応

**情報設計とナビゲーション**
- 画面は ホーム / スレッド / 診断 の 3 つ + 設定。タブ無し
- 図の文法: 上段 = 基準(前回/最も安定/お手本)、下段 = 今回。対応した音は結び線、弾き忘れは上段だけに中空マーカー、余分は下段だけにハッチ。結び線の傾きがそのまま時間のずれ(オフセットとテンポ差を除いた後の残差)
- 主導線: ホームのカードの 2 本線をタップ → スレッド画面で録音 → 停止すると下段が描き変わり、結び線が上から降りてくる

**主要 3 画面のスケッチ**
```
ホーム
┌──────────────────────────────────┐
│ 今日の一本                         │
│ Aメロのスライド      22ms(前回26) │
│ 前回 | |  |   | || |   |  |        │
│      | |  \   | || /   |  |        │
│ 今回 | |   |  | ||| |  |  |        │
│ [ ● 録る ]                          │
│──────────────────────────────────│
│ サビ前のフィル  31ms 横ばい         │
│   ||| |  || |  (2 本線のミニ)       │
│ イントロのリフ  40ms ばらついた      │
│   | | |○| |    (○=弾き忘れ)         │
└──────────────────────────────────┘
```
```
録音中
┌──────────────────────────────────┐
│ Aメロのスライド ♩=80              │
│ 前回 | |  |   | || |   |  |  |     │
│ 今回 | |  |   | |▌                 │
│            ↑ いまここ(0:05)        │
│                                    │
│  音が拾えた数 11 / 前回 14          │
│                                    │
│  [ ■ 止める ]                       │
│  (評価は止めてから。途中は数だけ)  │
└──────────────────────────────────┘
```
```
診断結果
┌──────────────────────────────────┐
│ ← 診断  相手:[直前▼]               │
│ ばらつき 26→22ms 小さい             │

│ 前回 | |  |   | || |  ○|  |        │
│      | |  \   | ||  \   |  |       │
│ 今回 | |   |  | ||   | ▨ |  |      │
│     1   5      10    15   20音     │
│ 7音目が 62ms 遅れ / 18音目が余分   │
│ [表で見る] [▶前回] [▶今回]         │
│ [ ● もう 1 回 ]   [ 一覧 ]          │
└──────────────────────────────────┘
```

**体験の核**: 結び線がほとんど垂直に揃っていて、1 本だけ斜めに倒れている箇所が「ここだ」と指で差せる瞬間。数字より先に形で分かる。

**数字の嘘をつかない**: 残差が 20ms 未満の結び線は垂直に丸めず実値で描くが、太さも色も変えない(強調は 80ms 超 = severity 1 以上だけ)。図の上の 3 項目は横ばい幅内なら灰の「横ばい」。テンポ差は結び線から除いたことを図の下に必ず書き、テンポを落とした回は上部に「テンポを落とした回は勝ち負けにしません」。

**練習中の配慮**: 録音中の下段はリアルタイムに伸びるので、離れていても「拾えているか」が分かる(評価は出さない)。停止は画面全体。結果の要点は 28px の 3 行で、図は近づいて見る前提。

**リスク・弱点**: 音数が 60 を超えると結び線が密になる → 横スクロール + 全体のミニマップが要る。リアルタイム表示には録音中の推論が必要で、現行は停止後に一括推論なので、録音中は「振幅のオンセット検出の簡易版」になり、最終結果と数が食い違う可能性。
**実装コスト**: M(SVG の新しい図 1 種 + ホーム縮小版。録音中のリアルタイム表示は後回しにできる)

## D03 タブ譜の上のズレ

**一言コンセプト**: ギタリストが普段読んでいる 6 本線のタブ譜を全画面の共通の地図にして、ズレ・弾き忘れ・余分をタブ譜の音符の上に印として置き、ホームの一覧は各スレッドの「タブ譜 1 小節の切れ端」で並べる。

**ビジュアル言語**
- 色: 紙 `#f9f6ef`(dark `#141412`)、線と数字 `#2b2a27`(dark `#e8e6df`)、今回の印 `#2a78d6`(dark `#3987e5`)、お手本・楽譜由来の印 `#eb6834`(dark `#d95926`)、前回 `#898781`
- タイポ: フレット数字は等幅(JetBrains Mono 系)16〜20px、見出しはサンセリフ。タブ譜の数字は表の縦揃えなので tabular 可
- 形: 6 本の 1px 線、印は数字を囲む輪(一致 = 無印、音高違い = 塗り輪、弾き忘れ = 破線輪ではなく中空の輪 + 斜線、余分 = ハッチ付き小さな四角)。遅れ/早めは数字の横に 2px の短い矢羽
- ライト/ダーク: 両対応(dark は黒板のような印象)

**情報設計とナビゲーション**
- 画面: ホーム(切れ端の束)/ スレッド(タブ譜全体 + 推移)/ 診断(タブ譜 + 指標)。タブ無し
- 弦の割り当ては音高から推定(最低フレット優先 + 直前の手の位置を保つヒューリスティック)。楽譜お手本(MusicXML)に弦・フレット情報があればそれを使う
- 主導線: ホームで切れ端をタップ → スレッドで録る → 診断はタブ譜の該当小節に自動スクロール

**主要 3 画面のスケッチ**

```
│ e|-----------------------|         │

│──────────────────────────────────│

│ G|--7h9--7--◎--|                   │
│ イントロのリフ      40ms            │
│ A|--0--3--▨--5-|                   │
└──────────────────────────────────┘
```
```
録音中
┌──────────────────────────────────┐
│ Aメロのスライド  ♩=80  ● 0:06      │
│ e|-----------------------------|   │
│ B|--5--7--8--7-----------------|   │
│ G|------------7--5--4--5-------|   │
│ D|-----------------------------|   │
│      ▲ いま 2 小節目(メトロノーム)│
│                                    │
│  [ ■ 止める ]                       │
│  前回の自分: 22ms                   │

```
```

┌──────────────────────────────────┐

│    ◌  = 弾き忘れ(G弦 5)           │
│ 弦は音高から推定しています          │
│ [ ● もう 1 回 ]   [ 一覧 ]          │
└──────────────────────────────────┘
```

**体験の核**: 「G 弦 5 フレットをいつも落とす」とタブ譜の言葉で分かり、そのまま左手の運指を見直せる瞬間。ギター練習の文脈に最も近い。

**数字の嘘をつかない**: 矢羽は残差 80ms 超(severity 1)の音にだけ付ける。それ未満は印を付けず「揺れの範囲」。弦の推定が外れても音高・時刻の診断は変わらないので、画面に「弦は推定」を常に明記し、推定を理由に数字を動かさない。3 項目の横ばい幅は共通ルールどおり。

**練習中の配慮**: フレット数字 20px で譜面台距離でも読める。録音中はメトロノームがあれば現在小節にカーソルを進める(ページ送りは自動)。和音スレッドはタブ譜の縦の数字の束 + コード名。

**リスク・弱点**: 弦・フレットの推定はアプリに無い新機能で、間違えるとギタリストほど違和感が大きい。曲通しや長いフレーズは横に長くなる。単音認識の精度(GAPS 90%)の外れ値がタブ譜上で「変な運指」に見える。
**実装コスト**: L(弦割り当て、タブ譜レンダラ、MusicXML の technical 要素の読み込み)

## D04 拍の時計

**一言コンセプト**: 1 拍(または 1 小節)を 1 周とする円盤の上に、今回の出だしを点で打ち、前回の自分の散らばりを灰の輪で重ねることで「拍のどこに音が落ちているか」を時計の針のように見せ、ホームの各スレッドも小さな時計盤にする。

**ビジュアル言語**
- 色: 面 `#1a1a19`(ダーク優先、light `#fcfcfb`)、目盛り `#383835`(light `#c3c2b7`)、今回の点 `#3987e5`(light `#2a78d6`)、前回の輪 `#898781`、お手本/楽譜の格子 `#c98500`(dark で PASS、light は `#eda100` がコントラスト WARN のため直接ラベル併用)
- タイポ: サンセリフ、中央に ms を 56px。目盛り数字 12px
- 形: 円、1px の目盛り、点 8px に 2px の面色リング(重なり分離)。四角いカードは使わず円盤が主役
- ライト/ダーク: ダーク基調 + ライト

**情報設計とナビゲーション**
- メトロノーム録音: 円周 = 拍位相(1 周 = 1 マス。16 分なら 1 マス 259ms など)、真上 = 格子。点の角度 = 早い/遅い
- メトロノーム無し: 円周 = 基準テイクの対応音からの残差(真上 = 残差 0、±半周 = ±格子相当)。「基準が動く」注記付き
- 画面: ホーム(時計盤の棚)/ スレッド(大時計 + 日ごとの小時計の列)/ 診断。タブ無し

**主要 3 画面のスケッチ**

```
│            · · · ·                 │

│ (◔)サビ前 31ms  (◑)リフ 40ms       │
│ (◕)C→G 判定なし                    │
│   各時計は最新テイクの点の集まり   │
└──────────────────────────────────┘
```
```

│ 一致率 88→91% 横ばい 弾き忘れ 3→1   │
```

**体験の核**: 点の塊が真上に寄っていく、あるいは「いつも少し遅れ側に傾いている」が一瞬で見えて、メトロノームとの関係が身体感覚に落ちる瞬間。

**数字の嘘をつかない**: 聴覚は小さなずれを大きく感じるので、同期再生ではオフセットとテンポ差を除いた後の残差だけを残し、横ばい幅(残差 20ms 未満)の音にはマーク音を鳴らさない。数字の 3 項目は共通ルールどおりの横ばい表記。「聴こえ方は再生環境で変わる」を注記し、音だけで勝ち負けを言わない。

**練習中の配慮**: 目を使わない。停止後の自動再生、音量ボタン/イヤホンのリモコンで再生・一時停止(Media Session API)。画面は大きな再生ボタンと 1 本の帯だけ。

**リスク・弱点**: イヤホン前提が強い(スピーカーでは左右が混ざる → 交互再生に自動で切替)。元音声の時間伸縮(テンポ差を除く同期)は音質劣化があり、実装が重い。音声を保存していないテイク・デモは合成音(playNoteEvents)になり、生演奏と印象が違う。
**実装コスト**: L(Web Audio の左右パン・区間再生・時間伸縮、Media Session)

## D09 ことばの診断書

**一言コンセプト**: 診断の第一表現を 2〜3 文の日本語にし(「前回とほぼ同じばらつきです。7 音目が今回も少し遅れました」)、数字と図はすべて折りたたみの「根拠」に入れ、ホームも各スレッドの最後のひと言が並ぶ練習ノートにする。

**ビジュアル言語**
- 色: 紙 `#f7f4ec`(dark `#161513`)、文字 `#23211d`(dark `#ece9e1`)、根拠の数字 `#52514e`(dark `#c3c2b7`)、今回を指す下線・点 `#2a78d6`(dark `#3987e5`)
- タイポ: 本文 22〜28px のサンセリフ(読み物だが hero 以外もサンセリフで統一)、行間 1.7。根拠は 14px
- 形: 罫線のみ、左に 3px の日付の縦線。角丸は折りたたみボタンだけ 8px
- ライト/ダーク: 両対応

**情報設計とナビゲーション**
- 文は定型文の組み合わせで作る(生成 AI は使わない。完全クライアントサイド、断定表現を排除できる)。文の順: ①ばらつきの方向 ②一番目立つ箇所 ③(あれば)弾き忘れ・テンポ。各文の末尾に「根拠 ▸」
- 画面: ホーム(ノート)/ スレッド(そのスレッドのページ)/ 診断(今日の段落)。タブ無し
- 主導線: ホームの最上段「今日の一本: 昨日は 7 音目が遅れがちでした」→ 録る → 段落が 1 つ増える

**主要 3 画面のスケッチ**
```
ホーム(練習ノート)
┌──────────────────────────────────┐
│ 今日の一本                         │
│ Aメロのスライド                    │
│ 「昨日は 7 音目が遅れがちでした。  │
│   今日もそこを聴いてみましょう」   │
│ [ ● 録る ]                          │
│──────────────────────────────────│
│ サビ前のフィル  3日前              │
│ 「前回とほぼ同じように弾けています」│
│ イントロのリフ  9日前              │
│ 「しばらく寝かせています」         │
└──────────────────────────────────┘
```
```
録音中
┌──────────────────────────────────┐
│ Aメロのスライド                    │
│                                    │
│        ● 録音しています            │
│            0:07                    │
│                                    │
│   「7 音目」                        │
│   (昨日遅れがちだった音)          │
│                                    │
│  [ ■ 止める ]                       │
└──────────────────────────────────┘
```
```
診断結果
┌──────────────────────────────────┐
│ ← 今日の段落                       │
│ 前回よりばらつきが少し小さく       │
│ なりました(26→22ms)。             │
│ 7 音目は今回も遅れ気味です(62ms)。│
│ 弾き忘れは 3 個から 1 個に。        │
│ ▸ 根拠を見る(6 指標・ズレの位置)  │
│ 同じように弾けているかの記録です。 │
│ 正しさの判定ではありません。       │
│ [ ● もう 1 回 ]   [ 一覧 ]          │
└──────────────────────────────────┘
```

**体験の核**: 数字を読まなくても、先生の一言のように「7 音目が遅れ気味」と分かり、次の 1 本で何に気をつけるかが決まる瞬間。

**数字の嘘をつかない**: 文のテンプレートは verdict の outcome に 1 対 1 で対応させ、横ばい幅内は必ず「ほぼ同じ」系の文にする(「少し小さく」は 4ms 以上のときだけ)。文中に必ず元の数字を括弧で添える。「上達」「良くなった」は辞書から除外し、テストで禁止語チェックを回す。判定なしは「今回は音が少なく、比べていません」と理由を言う。

**練習中の配慮**: 本文 28px。文を読み上げ(Web Speech API、端末内)できるので、画面を見なくてもよい。録音中は注目する 1 音だけ大きく。

**リスク・弱点**: 定型文は繰り返すと飽きる(組み合わせの数に上限)。数字好きの利用者には遠回り。言い回しが「断定しない」と「分かりやすい」の間で難しく、文言レビューのコストが継続的にかかる。
**実装コスト**: S〜M(文生成の純関数 + 折りたたみ UI。読み上げは任意)

## D10 ノイズの帯

**一言コンセプト**: すべての数字に「同じ演奏でも出る揺れの幅(ノイズ帯)」を一緒に描き、前回との差がその帯を越えたときだけ「変化」として扱う ―― 差が意味を持つかどうかを正直に見せることを、診断・推移・ホームの共通の文法にする。

**ビジュアル言語**
- 色: 面 `#fcfcfb`(dark `#1a1a19`)、ノイズ帯 `#e1e0d9`(dark `#383835`)、前回の点 `#898781`、今回の点 `#2a78d6`(dark `#3987e5`)、帯を越えた差の線 `#256abf`(dark `#5598e7`)
- タイポ: サンセリフ、数字 40px、帯の注記 13px。「±4ms」の表記を数字のすぐ横に常に出す
- 形: 帯は角丸 4px の横長の面、点 10px に 2px 面色リング、差の線は 2px。影なし
- ライト/ダーク: 両対応

**情報設計とナビゲーション**
- ノイズ帯の中身: 既定は verdict の横ばい幅(±4ms / ±5pt / ±1 音)。同じ日に同じスレッドを 3 本以上録ったら、その日のテイク間の揺れ(最小〜最大)を「自分のその日の揺れ」として帯に重ねる(帯が広がることはあっても、狭くして差を大きく見せる方向には使わない)
- 図の文法: 数直線の上に前回の点と帯、今回の点。点が帯の外 = 変化、帯の中 = 横ばい。推移グラフも各点に帯を付けた「帯付き折れ線」
- 画面: ホーム / スレッド / 診断。タブ無し。ホームのカードは「帯の中にいる / 帯より下 / 帯より上」を 1 本の数直線で

**主要 3 画面のスケッチ**
```
ホーム
┌──────────────────────────────────┐
│ 今日の一本  Aメロのスライド        │
│ ばらつき  0 ──[▓▓●▓▓]──○──── 40ms  │
│          今回 22  前回 26(帯の外) │
│ [ ● 録る ]                          │
│──────────────────────────────────│
│ サビ前  0 ─[▓○●▓]──── 31 横ばい    │
│ リフ    0 ───[▓○▓]─●─ 40 ばらついた│
│ ▓ = 同じ演奏でも出る揺れ(±4ms)    │
│ 解決候補 ●●●○○ 3/5                 │
└──────────────────────────────────┘
```
```
録音中
┌──────────────────────────────────┐
│ Aメロのスライド ♩=80  ● 0:06      │
│                                    │
│  0 ──[▓▓▓○▓▓▓]────── 40ms          │
│      前回 26ms と その揺れ幅        │
│                                    │
│  この帯の外に出たら「変化」        │
│  帯の中なら「横ばい」と表示します  │
│  [ ■ 止める ]                       │
│                                    │
└──────────────────────────────────┘
```
```
診断結果
┌──────────────────────────────────┐
│ ← 診断  相手:[直前] [安定] [お手本]│
│ ばらつき 0 ──●─[▓▓○▓▓]── 40ms      │
│   26→22ms 帯(±4)の外:前回より小さい│
│ 一致率  0 ─────[▓○▓●▓]─ 100%       │
│   88→91% 帯(±5pt)の中:横ばい      │
│ 弾き忘れ 0 [●▓▓○] 10               │
│   3→1 帯(±1)の外:前回より少ない  │
│ 今日 3 本の揺れ: 22〜27ms           │
│ [ ● もう 1 回 ]   [ 一覧 ]          │
└──────────────────────────────────┘
```

**体験の核**: 今回の点がはっきり帯の外に出たとき、「気のせいではない」と自分で納得できる瞬間。逆に帯の中なら「今日は揺れの範囲」と安心でき、数字の上下に一喜一憂しなくなる。

**数字の嘘をつかない**: この案はそれ自体が「横ばいの可視化」。帯の幅は判定と同じ定数(verdict.ts)から描き、図と判定が食い違わないようにする(境界ちょうどの扱い: ばらつき |Δ| < 4 は中、= 4 は外、を図でも同じに)。その日の揺れは帯を広げる方向にだけ使い、狭めない。判定なしのときは点を中空にして帯を描かない。

**練習中の配慮**: 1 本の数直線は 2 m 先でも点が帯の中か外か見分けられる(点 10px + 帯の濃淡差)。数字は 40px。録音中に前回の帯を見せておくと「何を目指すか」が数値目標より穏やかに伝わる。

**リスク・弱点**: 「帯」の概念の説明が要る(初回にだけ 1 行の説明)。固定の ±4ms は実際のノイズ(採譜の揺れ)と一致しない可能性があり、将来は実測(同じ演奏の繰り返し録音)で更新すべき。変化が帯の中に収まることが多く、画面が「横ばい」だらけに見えて手応えが弱い日がある。
**実装コスト**: S〜M(数直線の SVG 1 種 + 推移グラフに帯。定数は既存)
