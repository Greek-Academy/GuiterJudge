# ideas-C: 練習中のインタラクションから決める全体コンセプト(C01〜C10)

担当視点: 練習中のインタラクション(両手が塞がる / 譜面台のスマホを 1〜2 m 離れて見る / メトロノームとカウントイン / 録音の開始・停止 / 録り直しのループ)。

## 前提として押さえた現行実装の事実(全案に効く)
- `Recorder.start()` は `getUserMedia` → `MediaRecorder.start()`。その後 `Metronome.start()` が AudioContext を resume して先読みスケジューリング(25 ms 間隔、120 ms 先読み)。**録音開始とカウントイン 1 拍目の間に getUserMedia 分の遅延がある**ので、「押した瞬間にカウントが始まる」ように見せるには、マイクを先に開いておく(待機状態 = arm)設計が効く。
- `onBeat` は鳴る瞬間に setTimeout で UI に届く。視覚ビートは現状でも作れるが、setTimeout 由来の数 ms〜十数 ms の揺れがある(見た目用途なら十分)。
- クリックは 5 kHz / 6.5 kHz のサイン波 30 ms。**スピーカー再生前提**で、採譜の音域フィルタで落ちる。→ リアルタイムの音量検出(開始/停止の自動化)をやるなら、同じく 2 kHz 以上をローパスで落とせばクリックに反応しない。
- 停止 → `stopRecordingAndDiagnose` が decode + 採譜(数秒)→ 診断画面に遷移。**テイクは必ず保存され、破棄の導線が無い**。録り直しのループは「診断 → もう 1 回録る(autoRecord)→ スレッド詳細 → 自動開始」の 3 画面往復。
- 録音中はメトロノーム設定パネルが消え、`count-in` の数字と「♩=80 録音中」だけが出る。停止ボタンは通常サイズの `primary`。
- autoRecord はマイク許可済みのときだけ自動開始(許可ダイアログを「勝手に録音」に見せない配慮)。この配慮は全案で維持する。

以下の「最小の文字サイズ」は CSS px(Android の標準 DPR で約 0.16 mm/px 換算、1.5 m で読めるのは概ね 40 px 以上)、「最小のタップ領域」は CSS px の矩形。練習中(録音待機〜録音中〜直後)と、手元で操作する通常時(ホーム・設定)を分けて書く。

## C01 ワンボタン・ホール(巨大単一ボタン)
**一言コンセプト**: 練習中の画面にはボタンが 1 つしかなく、それが画面の下 60% を占め、状態(待機 / カウント / 録音 / 解析)によって色と文字だけが変わる。

**ビジュアル言語**
- 色: 待機 `#1F6FEB`(青)、カウントイン `#F2A900`(琥珀)、録音中 `#D7263D`(赤)、解析中 `#5B6470`(灰)、背景 `#FAFAF7` / ダーク `#101214`
- タイポ: 和文は Noto Sans JP Bold、数字は等幅に近い Inter Tight の Tabular。ボタン内ラベル 56 px、カウント数字 160 px。
- 形: ボタンは角丸 32 px の巨大な板(サウンドホールの円ではなく、押しやすさ優先の角丸長方形)。影なし、状態変化は塗りの色だけ。
- ライト/ダーク: 両対応。ダークでは板の色を 15% 暗くし、背景とのコントラスト比 4.5 以上を保つ。

**情報設計とナビゲーション**
- 全画面が「上 40% = 情報、下 60% = 1 枚のボタン」の同じ骨格。ホームのボタンは「今日の一本を録る」、スレッドでは「録る」、診断では「もう 1 回」。**どの画面でも同じ位置を叩けば録音に入る**。
- タブ無し。上部の情報領域を左右スワイプでスレッド切替。設定(BPM・音価・カウントイン)は情報領域をタップして開くシート。
- 主導線: 開く → 下半分を叩く → (カウント)→ 弾く → 下半分を叩く → 同じ板が「解析中」→ 上半分に結果、下半分は「もう 1 回」に変わる。**画面遷移ゼロで録り直しがループする**。

**主要 3 画面のスケッチ**
```

┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ 今日の一本            │   │ ♩=80  16分  2小節目   │   │ 前回の自分と比べて     │
│ Cメジャー上昇 3連     │   │                      │   │ ばらつき 18ms (前 24) │
│ 安定 ■■■□□           │   │  ● REC  0:12         │   │ 一致    92%  (前 90) │
│ ‹ 他のスレッド 4 ›    │   │                      │   │ 弾き忘れ 1   (前 1)   │
│                      │   ├──────────────────────┤   │ ▸ 詳しく見る          │
├──────────────────────┤   │██████████████████████│   ├──────────────────────┤
│██████████████████████│   │██████████████████████│   │██████████████████████│
│██                  ██│   │██     ■ 止める     ██│   │██   ● もう 1 回    ██│
│██   ● 録る          ██│   │██                  ██│   │██                  ██│
│██   ♩=80 カウント4  ██│   │██  (どこを叩いても) ██│   │██  ♩=80 そのまま   ██│
│██████████████████████│   │██████████████████████│   │██████████████████████│
└──────────────────────┘   └──────────────────────┘   └──────────────────────┘

**体験の核**: 弾き終わってピックを持ったまま板を叩くと、同じ場所がそのまま「もう 1 回」になっている瞬間。狙わずに叩ける。

**練習中の配慮**
- 最小の文字サイズ: 練習中 32 px(情報領域の補助行)、ボタンラベル 56 px、カウント 160 px。通常時 16 px。
- 最小のタップ領域: 練習中は録音ボタン 1 つで「画面幅 × 画面高の 60%」(360×480 px 相当)。情報領域のタップ対象も 64×64 px 以上。通常時 48×48 px。
- 録音開始時にピックで誤タップしても止まらないよう、停止は「タップ後 1.5 秒以内の 2 回目は無視」(二重タップ防止)。

**リスク・弱点**: 板が大きすぎて誤タップで録音が始まりやすい(ギターのネックがかすめる)。情報領域が狭く、診断の詳細は別画面行き。見た目が単調で「毎日開きたくなる」力は弱め。
**実装コスト**: S(既存の handleRecordToggle を 1 コンポーネントに集約し、状態で見た目を切り替えるだけ)

## C02 アーム&リッスン(音で始まり、無音で止まる)
**一言コンセプト**: 録音は「押して始める」のではなく「構えておく(アーム)」もので、最初の一音で記録が始まり、2〜3 秒の無音で自動的に閉じてそのまま次のアームに戻る。

**ビジュアル言語**
- 色: アーム待機 `#0E7C66`(深緑、マイクが聴いている)、記録中 `#E4572E`(朱)、閉じた直後 `#F4F1EA`(生成り)、文字 `#1B1B1B`、ダーク背景 `#0B0F0E`
- タイポ: 丸ゴシック系(M PLUS Rounded 1c)で柔らかく。状態ラベル 48 px、入力レベルの数値は出さない。
- 形: 画面中央に「耳」の輪(同心円 3 本、線 4 px)。音を拾うと輪が広がる。角丸 24 px のカード。
- ライト/ダーク: 既定はダーク(練習部屋は暗いことが多い)。ライトでも可。

**情報設計とナビゲーション**
- ホーム = 「今どのスレッドに耳を向けているか」。今日の一本を開くと即アーム(マイク許可済みのとき)。
- スレッド画面は「アーム中のまま」が標準状態。テイク履歴は下に畳まれ、録るたびに上に 1 行積まれる。
- メトロノーム ON のスレッドでは、**アーム中はクリックを鳴らし続け(録音はしない)**、1 拍目付近で音が入った小節頭から記録を始める(カウントインの概念が「弾き始めたいときに弾く」へ変わる)。クリック帯域(5 kHz)は検出前にローパスで除外。
- 停止は無音 2.5 秒(スレッドで 1.5/2.5/4 秒を選択)。曲通しは無音停止を無効にし、手動停止のみ。
- 主導線: 開く → (構えて弾く)→ 自動で閉じる → 画面上部に結果の要約が 1 行で出る → そのまま次のテイクへ。

**主要 3 画面のスケッチ**
```
[ホーム]                        [録音中]                        [診断結果(閉じた直後)]
┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ 耳を向けるフレーズ     │   │ Cメジャー上昇 3連     │   │ 閉じました 0:14       │
│ ┌──────────────────┐ │   │                      │   │ 前回比 ばらつき 24→18 │
│ │ 今日の一本        │ │   │      ((( ● )))       │   │        一致率 90→92  │
│ │ Cメジャー上昇 3連 │ │   │       記録中          │   │ ──────────────────── │
│ │ ◎ 開けば聴き始める │ │   │      0:09            │   │      ((  ◎  ))       │
│ └──────────────────┘ │   │                      │   │    また聴いています   │
│ ▸ ドロップD リフ      │   │ 止めるには 2.5 秒休む │   │  弾けば次のテイク     │
│ ▸ 曲通し: Blackbird  │   │ ▁▁▁▁▁▁▁▁░░ 無音ゲージ │   │ ──────────────────── │
│                      │   │                      │   │ [詳しく] [消す]       │
└──────────────────────┘   └──────────────────────┘   └──────────────────────┘
```

**体験の核**: 何も触らずに弾いて、休むと勝手に「閉じました、前回 24→18 ms」が出て、また聴いている状態に戻っている。ギターから手を離さずに 5 テイク録れる。

**練習中の配慮**
- 最小の文字サイズ: 練習中 36 px(前回比の 1 行)、状態ラベル 48 px。通常時 16 px。
- 最小のタップ領域: 練習中は操作不要が前提だが、アーム解除は画面上半分全体(360×400 px)。「消す」は 120×72 px。通常時 48×48 px。
- 無音ゲージを見せ、「止まるまであと何秒か」が離れて分かる。チューニング中や弦を押さえ直す雑音で始まらないよう、開始閾値はスレッドの最初の数テイクから学習。
- 自動で始まる性質上、**「消す」(直前テイクの破棄)を新設**。弾き損じの断片が履歴を汚さない。

**リスク・弱点**: 長い休符を含むフレーズで途中停止する。開始判定の遅れで頭の音が欠ける(→ 常時 1 秒のプリロールバッファを持ち、開始時に遡って含める必要があり、MediaRecorder 単体では難しく AudioWorklet で PCM を持つ実装に変わる)。常時マイクが開いていることへの不安(マイクインジケータ)。
**実装コスト**: L(AudioWorklet の常時録音 + リングバッファ + 開始/停止判定 + 破棄の DB 操作)

## C03 ペダル・ファースト(Bluetooth 譜めくりペダル前提)
**一言コンセプト**: アプリ全体を「左ペダル / 右ペダル」の 2 キーで一巡できるように作り、画面はその 2 キーが今何をするかを常に左右下端に大きく示す。

**ビジュアル言語**
- 色: 左ペダル `#3A86FF`、右ペダル `#FF7A00`、背景 `#F6F5F1` / ダーク `#15171A`、文字 `#111111` / `#EDEDED`、録音中の縁 `#E03131`
- タイポ: 見出しは IBM Plex Sans JP SemiBold、ペダル凡例 40 px。
- 形: 画面下端の左右に「靴底」形の凡例(角丸 40 px の半楕円)。本文カードは線 1 px、角丸 12 px。
- ライト/ダーク: 両対応。

**情報設計とナビゲーション**
- 市販の譜めくりペダルは多くが `ArrowLeft/ArrowRight` か `PageUp/PageDown`、一部は `Space/Enter` を送る。初回に「左を踏んで / 右を踏んで」で学習し、2 キーに正規化。タッチ操作も全部残す(ペダルは任意)。
- 全画面を「右 = 進む(録る / 止める / 次へ)、左 = 戻る・やり直す」の文法で統一。長押し(0.8 秒)で第 2 機能(右長押し = テイクを消す、左長押し = BPM −5 など)。
- ホーム: 右で「今日の一本」→ 録音待機。左右でスレッドを選ぶフォーカス移動。
- 診断: ページ単位(対戦カード → 格子ばらつき → ピアノロール → 6 指標)を右で送る。**譜めくりペダルの本来の用途(ページ送り)と一致**。
- 主導線: 右(開く)→ 右(録る、カウント)→ 右(止める)→ 結果 → 右(もう 1 回)/ 左(詳しく)。

**主要 3 画面のスケッチ**
```
[ホーム]                        [録音中]                        [診断結果]
┌──────────────────────┐   ┌══════════════════════┐   ┌──────────────────────┐
│ ▶ Cメジャー上昇 3連   │   ║ ● 録音中  0:11        ║   │ 1/4 前回の自分と      │
│   ドロップD リフ      │   ║                      ║   │ ばらつき  18ms  勝ち  │
│   Blackbird 曲通し    │   ║        3             ║   │ 一致率    92%   同じ  │
│                      │   ║     (2小節目 3拍)     ║   │ 余分      2     負け  │
│ ペダル: 接続済み       │   ║                      ║   │ 発見: 3拍目が早い傾向 │
│                      │   ║ ♩=80                 ║   │                      │
│                      │   ║                      ║   │                      │
│ ╭────────╮ ╭────────╮ │   ║ ╭────────╮ ╭────────╮ ║   │ ╭────────╮ ╭────────╮ │
│ │◀ 下へ  │ │ 録る ▶│ │   ║ │◀ 捨てる│ │止める▶│ ║   │ │◀ 次の頁│ │もう1回▶│ │
│ ╰────────╯ ╰────────╯ │   ║ ╰────────╯ ╰────────╯ ║   │ ╰────────╯ ╰────────╯ │
└──────────────────────┘   └══════════════════════┘   └──────────────────────┘
```

**体験の核**: 弾き終わりの最後の音を伸ばしながら右足で踏むと止まり、もう一度踏むと 4 カウントが始まる。手がネックから一度も離れない。

**練習中の配慮**
- 最小の文字サイズ: 練習中 40 px(ペダル凡例)、状態 32 px、カウント 200 px。通常時 16 px。
- 最小のタップ領域: ペダル凡例自体がタップ対象で各 160×96 px。その他 48×48 px。
- 「左 = 捨てる」は録音中のみ有効。停止と捨てるを踏み違えたとき用に、捨てた直後 5 秒は右で復元。
- ペダルが無い人にも同じ 2 択 UI がタッチで機能するので、ペダル前提でも閉じない。

**リスク・弱点**: ペダルを持っていない人には「2 択の大きなボタン」でしかない。キー送出がペダル機種によって違い、一部はキーリピートや HID の癖がある。PWA がバックグラウンド/画面ロック時はキーが届かない(→ Wake Lock 必須)。
**実装コスト**: M(グローバルな keydown ルーター + 学習 UI + 全画面の 2 択化)

## C04 ステージモニター(フルスクリーンの黒い返し)
**一言コンセプト**: 練習に入るとアプリはライブハウスの足元モニターのような黒い全画面になり、見るべき数字を 1 つだけ巨大に映し、それ以外の画面は「楽屋」(手元で触る場所)として明確に分ける。

**ビジュアル言語**
- 色: ステージ背景 `#000000`、主数字 `#F5F5F0`、録音ランプ `#FF3B30`、ビート `#00C2A8`、楽屋(通常画面)背景 `#F4F2EE`
- タイポ: ステージは狭幅の DIN 系(Barlow Condensed / 和文は Noto Sans JP Black)で数字 240 px。楽屋は Noto Sans JP 16 px 基準。
- 形: ステージは線も角丸も無し、全面ベタ。楽屋は角丸 16 px のカード、影あり。
- ライト/ダーク: 楽屋はライト/ダーク両対応、ステージは常に黒(OLED で省電力、画面の明かりが練習の邪魔をしない)。

**情報設計とナビゲーション**
- 2 層構造: 楽屋(ホーム / スレッド / 診断の詳細 / 設定)と、ステージ(録音待機・録音中・直後の 1 数字)。楽屋からステージへは「ステージに上がる」1 ボタン。ステージは Fullscreen API + Wake Lock。
- ステージの表示は時間で 3 段: 待機「♩=80 / 準備」→ 録音「拍番号」→ 直後「18 ms(前回 24)」の 1 数字。どの数字を出すかはスレッドごとに選べる(ばらつき / 一致率 / 完走時間)。
- ステージのどこかをタップ = 録る/止める。下スワイプ = 楽屋へ降りる。
- 診断の詳細(対戦カード、ピアノロール)は楽屋側。**練習後にまとめて見る**ことを想定し、ステージ中のテイクは楽屋で「今日のセット」として並ぶ。

**主要 3 画面のスケッチ**
```
[ホーム(楽屋)]                 [録音中(ステージ)]              [診断結果(ステージ直後)]
┌──────────────────────┐   ┌██████████████████████┐   ┌██████████████████████┐
│ 楽屋                  │   █ ●              0:12 █   █ テイク 3             █
│ 今日の一本            │   █                      █   █                      █
│ Cメジャー上昇 3連     │   █                      █   █    18               █
│ 安定 ■■■□□           │   █        3             █   █      ms             █
│ ┌──────────────────┐ │   █                      █   █  前回 24             █
│ │  ステージに上がる  │ │   █                      █   █                      █
│ └──────────────────┘ │   █  ● ● ● ○             █   █ タップ: もう 1 回    █
│ 今日のセット: 0 テイク │   █  ♩=80                █   █ ↓ 楽屋で詳しく       █
│ ▸ ほかのスレッド      │   █                      █   █                      █
└──────────────────────┘   └██████████████████████┘   └██████████████████████┘
```

**体験の核**: 暗い部屋で黒い画面に白い「18」が浮かび、下に小さく「前回 24」。演奏者の視線だけで結果を受け取れる、プロっぽい静けさ。

**練習中の配慮**
- 最小の文字サイズ: ステージ中 44 px(「前回 24」などの補助)、主数字 240 px。楽屋 15 px(本文 16 px)。
- 最小のタップ領域: ステージ全面(録る/止める)。楽屋 48×48 px。
- ステージでは誤操作を減らすため、タップの受付は「指 1 本・移動 20 px 以内」のみ。ネックが画面を擦っても反応しない。

**リスク・弱点**: 1 数字に絞るので、「一貫性の変化」を 1 指標に還元して断定的に見える恐れ(→「前回」との並記を必須にし、良し悪しの色は付けない)。Fullscreen 解除のブラウザ操作が分かりにくい。楽屋とステージの 2 世界で画面数が増える。
**実装コスト**: M(ステージ 1 画面の新設 + Fullscreen/Wake Lock。楽屋は現行画面の改装で段階移行可)

## C05 拍の壁(メトロノームの視覚ビートが画面全体)
**一言コンセプト**: メトロノームは「音と一緒に画面全体が脈打つもの」であり、アプリのあらゆる画面がそのスレッドのテンポで呼吸し、診断も「拍に対して自分がどこにいたか」で語る。

**ビジュアル言語**
- 色: 1 拍目 `#FFB000`(強い黄)、その他の拍 `#2D3142`、裏拍/最小音価 `#4F5D75`、ズレの早い側 `#3FA7D6`、遅い側 `#EE6C4D`、背景 `#0D1017`
- タイポ: 数字は幾何学系 Sans(Space Grotesk)。拍番号 180 px、小節番号 36 px。
- 形: 画面を縦 4 分割(4/4 なら)した「拍の柱」。1 拍ごとに該当の柱が光って 150 ms で減衰。角丸無し、柱の間に 4 px の溝。
- ライト/ダーク: ダーク既定。ライトでは柱の点灯を `#FFB000` → `#E09A00` に落として白背景でも眩しくしない。光の点滅は「減光モード」(明るさ変化 30% 以下、`prefers-reduced-motion` で自動)を用意。

**情報設計とナビゲーション**
- どの画面にも上端 8 px の「拍の帯」があり、そのスレッドの BPM で淡く点滅(音は出さない)。ホームでは各スレッドのカードが自分の BPM で呼吸している(速いフレーズは速く)。
- 録音画面は柱 4 本が全面。カウントインは柱が右から順に消えていく(4→3→2→1)ので、「次の 1 拍目で弾き始める」が数字を読まずに分かる。
- 診断: 「拍に対する安定度(格子ばらつき)」を主役に昇格し、4 本の柱それぞれに「その拍での平均ズレ」を縦のバーで重ねる。**3 拍目だけ遅れがち**が柱の色でわかる。メトロノーム無しのテイクは柱の代わりに直前テイクとの差。
- 主導線: ホームのカード(呼吸している)→ 画面タップで全面の柱 → カウント → 演奏 → 止める → 柱にズレが重なった結果。

**主要 3 画面のスケッチ**
```
[ホーム]                        [録音中]                        [診断結果]
┌──────────────────────┐   ┌─────┬─────┬─────┬─────┐   ┌─────┬─────┬─────┬─────┐
│▔▔▔▔▔ ♩=80 拍の帯 ▔▔▔▔│   │█████│     │     │     │   │  1  │  2  │  3  │  4  │
│ ┌──────────────────┐ │   │█████│     │     │     │   │     │     │ ▼遅 │     │
│ │ Cメジャー上昇 3連 │ │   │█ 1 █│  2  │  3  │  4  │   │ ±8  │ ±9  │ +22 │ ±7  │
│ │ ♩=80 ・ ・ ・ ・  │ │   │█████│     │     │     │   │ ms  │ ms  │ ms  │ ms  │
│ └──────────────────┘ │   │█████│     │     │     │   │     │     │     │     │
│ ┌──────────────────┐ │   │█████│     │     │     │   ├─────┴─────┴─────┴─────┤
│ │ ドロップD リフ    │ │   │ 5小節目     ● 0:18   │   │ 3 拍目が前回より遅め    │
│ │ ♩=120 ・・・・     │ │   │ タップで止める        │   │ 全体 18ms(前回 24)   │
│ └──────────────────┘ │   │                      │   │ [もう 1 回] [詳しく]  │
└──────────────────────┘   └──────────────────────┘   └──────────────────────┘
```

**体験の核**: 柱が 4→3→2→1 と消えて、1 本目が黄色く光った瞬間に弾き出せる。弾き終えると同じ柱に「3 拍目 +22 ms」が立つ。見たものと直前の体感がつながる。

**練習中の配慮**
- 最小の文字サイズ: 練習中 36 px(小節番号・経過時間)、拍番号 180 px。診断の柱内数値 28 px(手元で見る前提)。通常時 16 px。
- 最小のタップ領域: 録音中は全面(止める)。診断の「もう 1 回」は 180×88 px。通常時 48×48 px。
- 視覚ビートは `onBeat`(setTimeout 由来)ではなく、`AudioContext.currentTime` を requestAnimationFrame で読んで描く方式に変えて、音と光のズレを 1 フレーム以内に収める。
- 光過敏への配慮として、点滅は 3 Hz 超(BPM 180 超)で自動的に減光モード。

**リスク・弱点**: 画面の点滅が「目で合わせる」癖を作り、耳の練習にならない懸念。メトロノーム無しのスレッドでは柱が使えず、コンセプトが半分になる。3 拍子・6/8 の柱数変化と 16 分音符の表現が複雑。
**実装コスト**: M(rAF ベースの拍描画、拍ごとのズレ集計は gridTiming の拡張)

## C06 ループ・ステーション(止めずに録り続ける)
**一言コンセプト**: 1 回の練習は「セッション」という 1 本の長い録音で、メトロノームは止まらず、N 小節ごとに自動でテイクが切られて積み重なり、テイク同士の比較が演奏中にリアルタイムで積み上がる。

**ビジュアル言語**
- 色: レーン 1〜8 を順に `#4361EE` `#4CC9F0` `#7209B7` `#F72585`(繰り返し)、現在レーン `#FFFFFF` 縁、背景 `#14121B`、休みの小節 `#2A2733`
- タイポ: ルーパー機材風の角ばった Sans(Rajdhani / 和文 Noto Sans JP Medium)。レーン番号 48 px。
- 形: 横長のレーン(高さ 56 px、角丸 8 px)が縦に積み上がる。LED 風の小さな四角で拍を示す。
- ライト/ダーク: ダーク既定、ライトでは背景 `#F1EFF6`、レーン色は同じ。

**情報設計とナビゲーション**
- スレッドに「ループ長」(例: 2 小節)を持たせる。セッション開始 → カウントイン → 以後 2 小節ごとに「弾く 2 小節 / 休む 2 小節」を交互に繰り返す(休む区間は結果を見る時間)。録音は 1 本の MediaRecorder で連続、解析時にメトロノームの格子で切る(現行の `gridTimingForTake` のカウントイン切り出しを一般化)。
- 休み区間に直前ループの要約(ばらつき 1 数字)がレーンに書き込まれる。**次のループまでに見て、また弾く**。
- ホーム = セッション履歴(日ごとのレーンの束)。診断画面 = セッション内のレーン比較(最も安定したレーン、ばらつきの推移)。個々のレーンを開けば現行の対戦カードとピアノロール。
- 主導線: 開く → 始める(1 回だけ触る)→ 弾く/休むを何周でも → 止める(1 回だけ触る)→ セッション診断。

**主要 3 画面のスケッチ**
```

│ ループ 2小節 ♩=80     │   │ 弾く ■■□□ 2小節目    │   │ 1 ▇▇▇▇▇ 31ms          │
│                      │   │ ──────────────────── │   │ 2 ▇▇▇▇  26ms          │
│ 9/22 ▇▇▇▇▇▇ 6周       │   │ 1 ▇▇▇▇▇▇ 31ms        │   │ 3 ▇▇▇   22ms          │
│ 9/21 ▇▇▇▇ 4周         │   │ 2 ▇▇▇▇▇  26ms        │   │ 4 ▇▇▇   21ms          │
│ 9/19 ▇▇▇▇▇▇▇▇ 8周     │   │ 3 ▇▇▇▇   22ms        │   │ 5 ▇▇▇▇  25ms  疲れ?   │
│                      │   │ 4 ▶ 演奏中            │   │ …                    │
│ ┌──────────────────┐ │   │                      │   │ 最も安定: 4 周目       │
│ │  セッションを始める │ │   │                      │   │ 前回セッション比 -3ms │
│ └──────────────────┘ │   │ タップで終わる         │   │ [4 周目を詳しく]      │
└──────────────────────┘   └──────────────────────┘   └──────────────────────┘
```

**体験の核**: 休みの 2 小節で「22 ms」がレーンに書き込まれ、それを見てまた弾く。触らずに 10 周できるので、「引っかかるフレーズを反復する」という練習そのものと画面のリズムが一致する。

**練習中の配慮**
- 最小の文字サイズ: 練習中 36 px(レーンの数値)、状態行 40 px。通常時 16 px。
- 最小のタップ領域: 録音中は全面(終わる)のみ。通常時 48×48 px、レーン 1 本は幅いっぱい × 56 px。
- 休み区間を 0 にする「連続モード」も選べる(曲の一部のリピート練習)。
- ループ中の解析は 1 周ごとに Web Worker で採譜し、UI スレッドを止めない。解析が次の休みに間に合わない場合は「…」で表示し待たせない。

**リスク・弱点**: 1 周ごとに採譜を回すため、ローエンド Android で追いつかない可能性(蒸留モデル 4 MB 前提で要実測)。メトロノーム必須になり、自由テンポのフレーズや曲通しには不向き。データモデル(セッション → テイク)の追加が必要。
**実装コスト**: L(連続録音の切り出し、逐次解析、セッション層の DB 追加、診断画面の再構成)

## C07 スタンド横持ち(ランドスケープ専用の練習画面)
**一言コンセプト**: スマホを譜面台に横向きに立てた瞬間に練習画面へ切り替わり、横長の画面を「時間軸」として使い、左から右へ流れる自分の演奏を見る。縦持ちは手元でのブラウズ専用。

**ビジュアル言語**
- 色: 背景 `#FBFAF6` / ダーク `#121416`、現在テイクのノート `#2A78D6`(現行のアクセントを継承)、前回テイク `#A0A7B0`、拍線 `#D9D6CE`、録音 `#D62839`
- タイポ: Noto Sans JP、横画面の上下帯に 40 px、時間軸の小節番号 28 px。
- 形: 画面の中央 70% がピアノロール的な横帯(角丸無し、罫線 1 px)。左右の端 18% は縦長の「袖」ボタン(角丸 24 px)。
- ライト/ダーク: 両対応。

**情報設計とナビゲーション**
- 向きで役割を分ける: 縦 = ホーム・スレッド管理・診断の詳細(読む)。横 = 練習(録る・直後を見る)。`screen.orientation` の変化で自動遷移し、横でスレッドを開いていれば即、録音待機に入る。Android Chrome では Fullscreen 中に orientation lock も可能。

## C08 暗転(録音中は何も見せない集中モード)
**一言コンセプト**: 録音中の画面は真っ暗で、拍の小さな点すら出さず、耳と手だけで弾かせる。明転(停止)したときに初めて結果が現れ、「見ないで弾いた自分」と「前回の自分」を静かに並べる。

**ビジュアル言語**
- 色: 暗転 `#000000`、唯一の録音表示 `#3A0A0A`(ほぼ見えない暗い赤の縁 2 px)、明転後の背景 `#F3EFE6`(紙)、文字 `#23201C`、差分の強調 `#9C6B30`(茶、良し悪しの色ではない)
- タイポ: 明朝系(Noto Serif JP)で本の頁のような落ち着き。結果の数字 72 px、本文 18 px。
- 形: 紙の頁、罫線のみ、角丸 4 px、影無し。
- ライト/ダーク: 明転後はライト(紙)/ダーク(墨 `#1A1814`、文字 `#E8E2D6`)。暗転は常に黒。

**情報設計とナビゲーション**
- 練習は「幕」の単位。幕を上げる(録る)→ カウントインは**音だけ**(画面は既に暗転)→ 演奏 → 画面のどこかをタップ or 最後の音から 4 秒の無音で明転。
- 明転の演出: 0.6 秒でゆっくり明るくなり、最初に 1 行「今回は前回と比べて、出だしのそろい方が近い」(文章。数字は次の行)。数字 → 図の順に下へ開く。

- 診断画面は頁をめくる形(対戦カード → 拍 → ピアノロール)。
- メトロノームの視覚表示は設定で「ほのか」にできるが、既定は無し(耳で合わせる練習に寄せる)。

│ 第二章 ドロップD リフ │   █                      █   │                      │
│   前は 9 月 18 日      │   █                      █   │   18 ms   (前回 24)   │

│ │    幕を上げる      │ │   █                      █   │ 触れると もう一幕     │
│ └──────────────────┘ │   █  (画面に触れて明転)  █   │ めくると 詳しく ›     │

```
(録音中の画面に文字は無い。スケッチ内の括弧書きは最初の 3 テイクだけ 3 秒表示される案内)

**体験の核**: 暗闇で弾き終わって、ふっと明るくなった紙に「前回と比べて、出だしのそろい方が近い」と書いてある瞬間。スコアの圧が無く、自分の耳の感覚と答え合わせができる。

**練習中の配慮**
- 最小の文字サイズ: 暗転中 0(文字無し。初回案内のみ 32 px)。明転直後の文 32 px、数字 72 px、「前回」併記 28 px。通常時 16 px。

**実装コスト**: S〜M(暗転画面自体は S。要約文の生成ルールと頁 UI で M)

## C09 ゴースト・ラン(直前テイクの影が流れる)
**一言コンセプト**: 録音中、画面には直前の自分(またはお手本)の音符がゴーストとして右から左へ流れ、今の自分はその影に重なるように弾く。レースゲームのゴーストカーだが、勝ち負けではなく「同じように弾けるか = 一貫性」を体で感じる装置。

**ビジュアル言語**
- 色: ゴースト `#8EC5FF` の 35% 不透明、今の自分の入力 `#FFFFFF`、判定線 `#FFD166`、背景 `#0B1320`(夜の道路)、お手本ゴースト `#C3A6FF`
- タイポ: Inter / Noto Sans JP。流れの中の音名は出さない。上部帯 36 px、終了後の数字 64 px。
- 形: 縦に流れる 6 本の「弦のレーン」ではなく、音高を縦軸にしたピアノロール帯が右→左に流れる。判定線は画面左 30% の縦線。ノートは角丸 6 px のカプセル。
- ライト/ダーク: ダーク既定(ゴーストの半透明が映える)。ライトでは背景 `#F2F5FA`、ゴースト `#2A78D6` の 25%。

**情報設計とナビゲーション**
- スレッドを開くと、直前テイクがゴーストとして判定線手前で待機。録る → カウントイン中にゴーストの最初の音が判定線に近づいてくる(カウントインの視覚化を兼ねる)→ 演奏中はゴーストが流れ、自分の入力はリアルタイムの音量包絡(採譜ではなく onset だけ)として白い点で判定線上に打たれる。
- ゴーストの選択: 直前 / 最も安定 / お手本(= 現行の比較モード 3 つをそのまま「誰と走るか」に)。**比較モードの切替が録音前の選択に移る**。
- メトロノームありなら拍の格子上、なしならゴーストのテンポ(直前テイクの実時間)で流す。
- 停止後: 流れが止まり、ゴーストと今回のノートが同じ帯の上に重なって残る → そのまま診断(ピアノロールが主役)。対戦カードはこの重なりの上に 3 行。
- ホーム: 各スレッドのカードに「最後のゴースト」の小さなシルエット(ノート列の形)を表示。

**主要 3 画面のスケッチ**
```
[ホーム]                        [録音中]                        [診断結果]
┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ ゴーストと走る         │   │ 直前の自分と ● 0:07   │   │ 直前の自分と重ねて     │
│ ┌──────────────────┐ │   │       ┃               │   │ ▭▬ ▭▬  ▭▬ ▭ ▭▬        │
│ │ Cメジャー上昇 3連 │ │   │    ●  ┃  ░░  ░░       │   │    ▭▬  ▭▬▭  ▭▬        │
│ │ ▁▂▃▅▆▇ 最後の形   │ │   │  ●    ┃░░   ░░  ░░    │   │ ▭▬   ▭▬    ▭▬ ▭      │
│ └──────────────────┘ │   │ ●     ┃   ░░    ░░    │   │    ↑ ここだけ離れた    │
│ ┌──────────────────┐ │   │       ┃ ░░   ░░       │   │ ──────────────────── │
│ │ ドロップD リフ    │ │   │ いま  ┃ ゴースト→     │   │ ばらつき 18 (影 24)   │
│ │ ▇▅▇▅▇▅ 最後の形   │ │   │       ┃               │   │ 一致率   92 (影 90)   │
│ └──────────────────┘ │   │ 誰と: [直前][最安定]  │   │ 次の影にする? [はい]  │
│                      │   │ タップで止める         │   │ [もう 1 回] [ほかの影] │
└──────────────────────┘   └──────────────────────┘   └──────────────────────┘
```

**体験の核**: カウントインの間に影の最初の音が判定線へ近づいてきて、ちょうど重なる瞬間に弾き出す。弾いている最中に「影より少し前に出た」が分かり、終わると重なった 2 本の列が残る。

**練習中の配慮**
- 最小の文字サイズ: 練習中 32 px(上部帯・下部の案内)。ノートの高さ最小 12 px(音高の差を 1.5 m で識別できる下限)。停止後の数字 64 px。通常時 16 px。
- 最小のタップ領域: 録音中は全面(止める)。ゴースト選択は録音前のみで 120×64 px。通常時 48×48 px。
- 演奏中の自分の入力は onset のみ(AnalyserNode で数十 ms 単位)、採譜は停止後。リアルタイムに音高判定を出さないので「間違えた」が演奏中に表示されない(責めない)。
- 「目で追う」依存を避ける設定として、ゴーストの流れを最初の 2 小節だけにする「出だしだけ」オプション。

**リスク・弱点**: ゴーストに合わせて弾くと、一貫性の指標が「影を見て合わせた結果」になり、耳での再現性の測定が歪む。ゴーストが競争を連想させ、ゲーミフィケーションと受け取られる恐れ(「勝ち」という語を使わない、色で勝敗を付けない)。メトロノーム無しの直前テイクはテンポが揺れるので、流すと不自然。
**実装コスト**: L(canvas での流れる描画、onset のリアルタイム検出、比較モードの前倒しと診断の再構成)

## C10 ギターがリモコン(声を使わず、ギター自身の音で操作する)
**一言コンセプト**: 声のコマンドを使わない代わりに、ギターで出せる「演奏とは区別できる合図」(ボディを 2 回ノック、全弦ミュートのチャッ 2 回)を開始・停止・録り直しの操作に割り当て、スマホに一切触れない練習を作る。

**ビジュアル言語**
- 色: 合図待ち `#6C757D`、合図を検出 `#FFC300`(一瞬の点灯)、録音中 `#C1121F`、背景 `#F7F4EF`(木目の明るい色) / ダーク `#1C1712`(ローズウッド)、文字 `#2B2118`
- タイポ: Noto Sans JP、合図の凡例をアイコン + 40 px で常時表示(「コンコン = 録る/止める」「チャッチャッ = 捨てて録り直す」)。
- 形: 合図の凡例はギターのボディ輪郭をかたどったアイコン。カードは角丸 20 px、線 2 px の木目調ではなくフラット。
- ライト/ダーク: 両対応。

**情報設計とナビゲーション**
- 合図の語彙は 3 つだけ: ① ボディのノック 2 回(0.5 秒以内)= 録る/止める、② ブラッシング(全弦ミュートのストローク)2 回 = 直前テイクを捨てて即カウントイン、③ ノック 3 回 = 今日はここまで(ホームへ)。
- 検出は録音待機中に AudioWorklet で常時(クリック帯域 5 kHz はローパスで除外)。ノックは「低域の衝撃 + 音程なし」、ミュートストロークは「広帯域ノイズで音程なし、短い」で演奏音と区別。検出の直後に短い確認音(採譜帯域外の高域)を鳴らして耳で分かるようにする。
- 録音の先頭/末尾に入った合図の音は、合図の検出時刻でトリムして採譜対象から外す。
- ホーム: 今日の一本 + 「合図で操作中」の表示。初回に合図の練習画面(3 回ずつ試して、その人のギターと部屋で閾値を合わせる)。
- 診断: 停止の合図の 1 秒後に要約(3 項目)が大きく出て、さらに次の合図(ノック 2 回)で次のテイクに入る。詳細は手に取って見る。

**主要 3 画面のスケッチ**
```
[ホーム]                        [録音中]                        [診断結果]
┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ 今日の一本            │   │ ● 録音中 0:10  ♩=80  │   │ 前回の自分と          │
│ Cメジャー上昇 3連     │   │                      │   │ ばらつき 18 (前 24)   │
│ ──────────────────── │   │        2             │   │ 一致率   92 (前 90)   │
│ 合図を聴いています     │   │                      │   │ 余分      2 (前  1)   │
│                      │   │                      │   │ ──────────────────── │
│ [叩] コンコン  録る      │   │ [叩] コンコン  止める   │   │ [叩] コンコン  もう1回  │
│ [払] チャッチャッ 捨てる  │   │ [払] チャッチャッ 捨てる │   │ [払] チャッチャッ 今のを │
│ [叩] コンコンコン 終わる │   │                      │   │                捨てる │
│                      │   │                      │   │                      │
│ [合図の練習] [手で録る]│   │ (画面タップでも止まる)│   │ [詳しく見る]          │
└──────────────────────┘   └──────────────────────┘   └──────────────────────┘
```
([叩][払] は説明用の記号。実装ではボディ/手のアイコン SVG)

**体験の核**: 弾き終えた右手でそのままボディを「コンコン」と叩くと、ピッと鳴って止まり、1 秒後に結果が出る。もう一度「コンコン」で次のテイク。ギターという楽器の身振りの中に操作が溶け込む。

**練習中の配慮**
- 最小の文字サイズ: 練習中 40 px(合図の凡例)、状態 36 px、拍番号 160 px。通常時 16 px。
- 最小のタップ領域: 合図が効かないときの保険として、録音中は全面タップで停止。凡例の各行もタップ可能で 320×72 px。通常時 48×48 px。
- パーカッシブ奏法(ボディヒット)を使うフレーズのスレッドでは合図を無効にする切替を持つ。
- 合図検出の確認音で「今、合図として取られた」がわかるので、誤検出にすぐ気づける。誤って止まった場合は「チャッチャッ」で捨てて録り直せる。

**リスク・弱点**: 検出精度が機材・部屋・ギター(エレキの生音 / アンプ経由 / アコギ)で大きく変わる。スラップやミュートカッティングを含む演奏で誤検出。エレキをライン録りしない前提(マイクで拾う)でノックが小さすぎることがある。常時マイクの AudioWorklet が必要で、C02 と同等の基盤コスト。
**実装コスト**: L(リアルタイム信号処理と個人差の較正、合図のトリム)

## 横断メモ(どの案を採っても効く小さな改善)
- **マイクの先開き(アーム)**: 録音ボタン押下 → getUserMedia 待ち → カウントイン、の遅延を消すため、スレッド画面を開いた時点(許可済みなら)でストリームだけ取得しておく。C01/C03/C04/C05 で「押した瞬間にカウント」が成立する。
- **テイクの破棄導線**: 現行は全テイクが保存される。練習の録り直しループには「今のは捨てる」が必須(C02/C03/C07/C10 で明示)。
- **Wake Lock**: 譜面台に立てたまま画面が消えるのが最大の実害。全案で録音待機〜直後の画面で `navigator.wakeLock.request('screen')`。
- **停止直後の待ち(採譜数秒)**: 待ちの間も「もう 1 回」を先に押せるようにし、解析はキューで後追いにすると、録り直しのテンポが途切れない。
