# デザインコンペ 共通ブリーフ(2026-09-23)

## お題
ギター上達診断 PWA(/Users/yk/dev/guitar-diagnosis/app)の **フロントエンド全体のデザイン(UI と UX)を全面的に作り直す** 前提で、全体コンセプト案を出す。現行の見た目・画面構成・遷移に縛られなくてよい。機能(できること)とデータは現行を引き継ぐ。

## プロダクトの芯(変えない)
- 独学のギタリストが「引っかかるフレーズ」をスレッドとして登録し、録音したテイクを **過去の自分** と比べ、一貫性(ばらつき ms、音符一致率、弾き忘れ/余分、テンポ差)の変化を見る。
- スコアは **正しさではなく一貫性** の指標。「上達した」と断定しない。空白を責めない。ストリーク・XP・ランキング・通知は採用しない(PRD Non-goal)。
- 完全クライアントサイド、アカウント無し、オフライン PWA。
- 主な利用端末は **Android スマホ(Chrome)**、縦持ち。練習中は両手がギターで塞がる。1 回 5〜15 分。

## 現行の機能(引き継ぐもの)
- スレッド一覧(アクティブ / 解決済み)、スレッド作成(単音フレーズ / 和音の練習 / 曲通し)
- スレッド詳細: 録音(マイク、メトロノーム + カウントイン、最小音価、最低音=変則調弦)、音声/動画ファイル取り込み、お手本(講師録音、既存テイク昇格、楽譜 MusicXML 取り込みパネル)、テイク履歴、推移グラフ、解決(自己確認 3 択)
- 診断画面: 前回の自分との対戦カード(3 項目の勝敗、発見)、拍に対する安定度(格子ばらつき)、6 指標、比較モード切替(直前 / 最も安定 / お手本)、ピアノロール(ズレの可視化)、和音はコードタイムライン、明日の予告、固定の「もう 1 回録る」バー
- 毎日の型: ホームの「今日の一本」hero、今日のまとめ、明日の予告、安定ゲージ(5 目盛り、満タンで解決候補)、スレッドの冷え(温度バー)
- 曲通し(完走時間の記録)、検証画面(推論エンジン切替、開発者向け)、デモデータ、バックアップ

## 現行デザイン
- 420px 固定の「スマホ枠」(スマホ幅では全画面)、白〜生成りの背景 #f9f9f7、黒文字、アクセント青 #2a78d6、カード + 角丸、ライトモードのみ。
- 画面は 5 つ(一覧 / 詳細 / 診断 / 曲通し / 検証)を App.tsx の useState で切り替え。ルーター・モーダル無し。タブバー無し。
- 実装: React 19 + TypeScript + 素の CSS(App.css 約 400 行、CSS 変数)。UI ライブラリ無し。

## 審査の観点(提案者も意識すること)

5. 設計思想との整合(断定しない、責めない、通知なし)

## 1 案の書式(全員共通)
各案は **アプリ全体のコンセプト** として書く(部分的な改善案ではなく、全画面に通る方針)。
- **ID と名前**(例: V03 アンプパネル)
- **一言コンセプト**(1 文)
- **ビジュアル言語**: 色(具体的な HEX を 3〜5 個)、タイポ(書体の系統とサイズ感)、形(角丸・線・影)、ライト/ダーク
- **情報設計とナビゲーション**: 画面構成、主導線(開く→録る→見る)、タブやモードの有無
- **主要 3 画面のスケッチ**: ホーム / 録音中 / 診断結果 を ASCII で各 10〜15 行
- **体験の核**: この案で一番気持ちいい瞬間はどこか
- **練習中の配慮**(手が塞がる、離れて見る)
- **リスク・弱点**と **実装コスト(S/M/L)**
