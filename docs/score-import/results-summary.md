## 2. MuseScore Studio 4.7.5 の MIDI 書き出しを正解にした突き合わせ(同音・開始時刻差 40 ms 以内)

MuseScore の MIDI は五線・TAB の 2 トラックに同じ音を書くので、片側トラックの音数と比べる。

| 曲 | 含まれる要素 | 本試作の音数 | MuseScore 1 トラックの音数 | 一致 | 不一致の内訳(調査済み) |
|---|---|---|---|---|---|
| 030 Oblivion | ドロップ D、タイ 8、装飾音 4、連符 24、和音、arpeggiate | 496 | 496 | 488(98.4%) | 装飾音 3(MuseScore は 16 分の長さで前打、本試作は 70 ms)、終止和音 5(MuseScore が `<arpeggiate>` を 63 ms ずつ崩す) |
| 071 | 反復 2 ブロック+volta(2 番括弧の開始小節に次ブロックの反復開始が同居)、装飾音 18、連符 56 | 419 | 419 | 401(95.7%) | 18 = 装飾音すべて(配置の慣習差のみ) |
| 081 | 反復ブロックの「1.」括弧が反復終端の 1 小節手前で閉じる譜面、開始無しタイ 8、フェルマータ 5、装飾音 42、ピックアップ小節 | 698(37 → 51 小節) | 658 | 643(92%) | 残り 55 は装飾音(42)と開始無しタイの和音(arpeggiate 崩し)。フェルマータ ×2 の実装前は 30 音、括弧の扱いを直す前は 423 音の一致だった |

| 049 | 拍子変更、テンポ記号 20 個(同位置に 6 個重複)、休符のフェルマータ、トレモロ 34、反復 | 2,479 | 2,616 | 2,164(87%) | 残差の中央値は全区間で 8 ms 以内。MuseScore 側が 137 音多いのは `<ornaments><tremolo>` 34 個を連打に展開しているため(本試作は 1 音のまま)。休符フェルマータ・同位置テンポ重複(最初を採用)を直す前は 923 → 1,713 音の一致だった |

同一曲の Soundslice 版 `.xml` / MuseScore 版 `.musicxml`(`<octave-change>-1`) / 圧縮 `.mxl` は 3 形式とも同じ 496 音を出力した。
`.mxl` はブラウザと同じ `DecompressionStream('deflate-raw')` 経路(Node 24 の同 API で確認)で 33 ms。

この突き合わせで見つけて直した試作の不具合: (1) `<direction>` に複数の `<direction-type>` がある時に metronome を見落とす(GAPS 98 曲でテンポ未取得)、
(2) volta を飛ばした時に反復回数を消して 2 番括弧まで飛ばす、(3) `times` 無しの反復回数に終端の後ろの最終括弧(「4.」)を数えない、
(4) 2 番括弧の開始小節に次ブロックの反復開始が同居する譜面(071)の処理順、(5) フェルマータ(音符・休符・タイ末尾)の伸長、
(6) 同位置のテンポ記号重複、(7) 「1.」括弧が反復終端の手前で閉じる譜面(081)で反復が展開されない。
MusicXML の反復・volta は仕様が緩く、書き出し元ごとの癖が多い領域なので、実装時は同種の回帰テストを必ず持つこと。

## 4. 比較ロジック(app/src/comparison.ts のコピー)への適合 — `proto/sim.ts`

Oblivion の楽譜から作った格子どおりのお手本に、模擬演奏(テンポ比・開始オフセット 400 ms・ジッタ σ25 ms・ルバート・弾き忘れ・余分)を
当てて `diagnose()` を通した。「事前正規化」= テイクの最初の音〜最後の音の長さ比でテンポを合わせてから渡す案。

単旋律(同時刻は最高音のみ、間隔 300 ms 以上 = SPEC 2 節の守備範囲)、8 小節 55 音・23 秒:

| ケース | 対応 | 弾き忘れ+余分 | 一致率 | ジッタ ms | 推定テンポ差 % | 真のテンポ差 % | 事前正規化: 対応 / 弾き忘れ+余分 / 一致率 / ジッタ |
|---|---|---|---|---|---|---|---|
| 同一 | 55 | 0 | 1.00 | 0 | 0 | 0 | 55 / 0 / 1.00 / 0 |
| ジッタのみ | 55 | 0 | 1.00 | 26 | 0.06 | 0 | 55 / 0 / 1.00 / 26 |
| テンポ 5% 遅い | 46 | 18 | 0.52 | 313 | 0.37 | 5 | 55 / 0 / 1.00 / 25 |
| テンポ 25% 遅い | 41 | 28 | 0.42 | 299 | -1.68 | 25 | 55 / 0 / 1.00 / 21 |
| テンポ 67% 遅い | 34 | 42 | 0.53 | 271 | 1.62 | 67 | 55 / 0 / 1.00 / 16 |
| ルバート ±8% + 10% 遅い | 46 | 18 | 0.46 | 268 | 0.06 | 10 | 48 / 14 / 0.77 / 246 |
| ルバート + 弾き忘れ 5% + 余分 5% + 音程ミス 3% | 44 | 19 | 0.39 | 254 | -0.09 | 10 | 44 / 19 / 0.82 / 306 |

16 小節 86 音・48 秒では劣化がさらに大きい(テンポ 5% で対応 60/86、一致率 0.42。事前正規化で 86/86・1.00)。
和音を含む元の 8 小節 71 音では、ジッタのみでも 65/71(和音内の音の順序が入れ替わると系列アライメントが対応を切る)。

読み取り: 現行の 2 パス直線フィットは「1 パス目のアライメントがほぼ正しい」前提で、テンポ差が数 % を超える 20 秒以上の
フレーズでは 1 パス目が崩れて回復しない(推定テンポ差がほぼ 0% に張り付いている = フィットが効いていない)。
純粋なテンポ差は事前正規化で完全に吸収できるが、ルバートには効かない(区分線形かスロープ制約付き DTW が必要)。
